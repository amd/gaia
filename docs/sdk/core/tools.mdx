Tools are synchronous Python functions exposed to the model. The decorator records
metadata and returns the original callable unchanged. Registration alone does not
run a tool, authorize an action, or supply an agent instance as `self`.

## Decorator contract

```text
@tool(atomic=False, display_label=None, timeout=None)
def get_note(note_id: int) -> dict:
    ...
```

This is the declaration shape; the function must have a real implementation.
`@tool`, `@tool()`, and `@tool(...)` are supported. Only `atomic`, `display_label`,
and `timeout` are accepted keyword options. Unsupported options such as `name`,
`description`, or `requires_confirmation` raise `TypeError`.

| Metadata | Source and behavior |
|---|---|
| Name | Function `__name__`; registering the same name replaces its global entry. |
| Description | Function docstring. |
| Parameters | Signature annotations and whether each parameter has a default. |
| Parameter descriptions | Google-style `Args:`, `Arguments:`, or `Parameters:` sections. |
| `atomic` | Marks a tool as suitable for direct execution without multi-step planning. It is not a transaction or permission flag. |
| `display_label` | Optional progress label for UI consumers. |
| `timeout` | Seconds to wait for the tool; `None` uses the global timeout. |

The return annotation does not enforce a return schema. Use JSON-serializable,
bounded values so the model can consume the result without ambiguous conversion.

## Register functions inside the agent

[`examples/notes_agent.py`](https://github.com/amd/gaia/blob/main/examples/notes_agent.py)
uses this concrete registration pattern:

```python
    def _register_tools(self):
        agent = self

        @tool
        def list_notes() -> dict:
            """List all notes with their IDs, titles, and creation dates."""
            notes = agent.query(
                "SELECT id, title, created_at FROM notes ORDER BY created_at DESC"
            )
            return {
                "notes": notes,
                "count": len(notes),
                "message": f"Found {len(notes)} note(s)",
            }
```

This excerpt belongs inside the example's `NotesAgent`, which initializes
`DatabaseMixin`. Nested functions capture the instance. Decorating an unbound
class method registers its `self` parameter too; the dispatcher does not bind it.

The decorator writes to a process-global registry. `Agent._snapshot_tools()` copies
the current registry into that instance, after which its dispatch and schema
building use the copy. Without a snapshot, the agent reads the shared registry.
A snapshot also copies whatever was already registered: it does not select only
the tools belonging to that class. Hosts constructing multiple agents must manage
registration order and isolate their effective tool sets deliberately.

Use `agent.get_tools_info()` or `agent.get_tools()` to inspect an agent's effective
tools. `get_tool_metadata(name)` reads the **global** registry and returns `None`
when the name is absent; it is not an instance-specific inspection API.

## Argument schemas and validation

| Python annotation | Registry type |
|---|---|
| `str` | `string` |
| `int` | `integer` |
| `float` | `number` |
| `bool` | `boolean` |
| `list`, `tuple`, `set`, `frozenset` | `array` |
| `dict` | `object` |
| `Optional[T]`, `T \| None` | Type of `T`, when the union has one non-`None` member |
| Generic containers such as `list[str]` | Container type; not a complete nested schema |
| Missing or unsupported annotations, multi-type unions | `unknown` |

A default value makes a parameter optional. `Optional[str]` without a default
still requires the argument. Postponed annotations are resolved when possible.
Write explicit validation in the function for ranges, paths, allowed values, and
nested structures; the decorator is not a full schema validator.

Before dispatch the harness checks missing required arguments, rejects unexpected
arguments unless the function accepts `**kwargs`, and attempts supported scalar
coercions. Malformed arguments return structured errors. It does not guarantee
that a model-generated path, URL, or command is appropriate for your application.

## Confirmation and policy

`Agent._execute_tool()` applies the host's policy-refusal hook before offering a
confirmation. Confirmation is required for the union of the base tool-name set
and the subclass's `CONFIRMATION_REQUIRED_TOOLS`. Dynamically registered entries
can carry `requires_confirmation`; `mcp_` tools without an explicit classification
require confirmation by default.

Declare new sensitive native tools in `CONFIRMATION_REQUIRED_TOOLS`. The decorator
does not infer destructive behavior from the body, docstring, or `atomic` flag.
An explicit scoped skill grant may cover a particular call; it does not blanket
approve every invocation of the tool.

A denial returns `{"status": "denied", "error": ...}`. A handler that cannot ask a
human denies unless unattended approval was explicitly enabled. Tool bodies called
directly bypass harness checks. See [Output handlers](/sdk/core/console) for how
terminal and UI decisions are collected.

## Errors

Ordinary exceptions raised by a dispatched tool are caught, recorded, and returned
to the loop as structured errors with execution context. Raising an exception does
**not** inherently crash the agent. The loop can enter recovery, but recovery is
bounded and not guaranteed to succeed.

Return a clear `status="error"` result for expected domain failures when you can
provide a useful explanation. Let unexpected failures retain their diagnostic
information. Do not swallow exceptions or return an empty success value. A returned
tool error and the query's top-level `status` are different contracts: inspect
both the final result and its recorded errors when building a host.

## Timeouts and cancellation

A tool runs in a daemon worker thread. The default wait is **180 seconds**, resolved
from `GAIA_AGENT_TOOL_TIMEOUT` at call time; `@tool(timeout=...)` overrides it.
Set a positive timeout suitable for the operation, and set network/subprocess
timeouts inside the tool as well.

When the wait expires, the harness signals the worker's cancellation flag and
returns a timeout error. Python cannot kill the thread: an abandoned tool may still
finish or produce side effects. A retry may overlap it. Long-running tools should
poll `tool_cancelled()` or call `raise_if_cancelled()` between stages; the latter
raises `ToolCancelled`. These helpers observe the per-tool timeout signal, not a
general guarantee that every UI stop has interrupted the tool body.

For SDK tests, test the tool function's validation and failure behavior directly,
then exercise harness dispatch separately to cover confirmation, malformed
arguments, and timeouts. Keep model/backend integration tests separate from these
deterministic checks.

See [Agent harness](/sdk/core/agent-system) for loop limits and context truncation,
and [MCP integration](/sdk/infrastructure/mcp) for remote tool registration.
