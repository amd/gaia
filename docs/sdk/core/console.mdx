An output handler receives progress, tool activity, errors, and final answers from
the [agent harness](/sdk/core/agent-system). It also owns the interface for asking
the user to approve a gated tool. Rendering and authorization are separate:
suppressing narration does not approve actions.

## Choose a handler

| Handler | Role | Important behavior |
|---|---|---|
| `AgentConsole` | Python CLI renderer with Rich formatting, progress, and previews | Prompts for confirmation when both stdin and stdout are terminals. It is not the TUI application. |
| `SilentConsole` | Suppress routine narration | By default still prints final answers and explicitly requested statistics. Terminal confirmation remains active. |
| `gaia.ui.sse_handler.SSEOutputHandler` | Agent UI/host event queue | Emits typed events, supports user decisions and cancellation. |
| `gaia.api.sse_handler.SSEOutputHandler` | Separate API server event adapter | Queues agent events; has no interactive approval round trip and denies gated tools by default. |

These two classes share a name but have different event queues and decision
capabilities. Neither handler alone is an HTTP server or an OpenAI streaming
response. Its host consumes and serializes the events.

## Inject a console

The following uses the source checkout's complete NotesAgent example:

```python
from examples.notes_agent import NotesAgent
from gaia.agents.base.console import SilentConsole

handler = SilentConsole(silence_final_answer=True)
agent = NotesAgent(output_handler=handler)
result = agent.process_query("List my notes")
print(result["result"])
```

`output_handler` takes precedence over the default console selected by
`silent_mode`. When overriding `_create_console()` in an agent subclass, preserve
silent behavior yourself or delegate to the base implementation.

`SilentConsole(silence_final_answer=True)` suppresses final-answer rendering as well
as narration. It does not disable logging, explicitly requested statistics, or
interactive consent. Do not interpret `SilentConsole()` as a promise of zero bytes
on every output channel.

## Confirmation behavior

The harness decides **whether** a call requires approval; the handler obtains the
decision. Native name sets, runtime MCP metadata, and scoped skill grants are
described in [Tools](/sdk/core/tools#confirmation-and-policy).

| Host situation | Decision behavior |
|---|---|
| Terminal console with interactive stdin and stdout | Shows the tool and literal arguments; accepts yes, otherwise defaults to no. Ctrl-C and EOF deny. |
| Terminal call with a safely representable session scope | Can offer an “always” grant for that invocation scope, not blanket permission for an arbitrary tool. |
| Piped stdin, redirected stdout, or broken terminal | Denies with an explanation because a visible, answerable prompt is unavailable. |
| UI SSE handler | Emits `permission_request`, waits for `resolve_tool_confirmation()`, and denies on cancellation or timeout. The wait bound is configurable by the host. |
| Handler using the base decision implementation | Denies unless explicit unattended approval applies. |

Session grants are owned by the handler. `reset_tool_approvals()` clears them.
Confirmation waits are tracked separately from tool execution time.

For an intentionally unattended trusted run, a library host can construct
`AgentConsole(auto_approve_gated_tools=True)` or
`SilentConsole(auto_approve_gated_tools=True)`. Operators can set
`GAIA_AUTO_APPROVE_TOOLS=1` in the launching environment. The environment opt-in is
read from the process environment captured before project `.env` loading; a
project-local `.env` cannot silently enable it. Approvals through this bypass are
logged. It bypasses confirmation gates, not every independent policy check.

## Implementing a host adapter

`OutputHandler` is an abstract interface. Its required methods cover processing and
step starts, state/thought/plan display, tool progress, errors, final answers,
completion, JSON, and progress indicators. Additional methods support prompts,
streaming, and statistics. Inspect its abstract
methods in the linked source when implementing a new adapter rather than copying a
partial interface into a host.

For a narrow customization, subclass `AgentConsole` or `SilentConsole` and override
the relevant rendering methods. A full GUI adapter must also handle:

- Queuing events safely while synchronous `process_query()` runs in a worker.
- Showing the exact pending call and routing a decision back to `confirm_tool_execution()`.
- Distinguishing a human denial from timeout, cancellation, or unavailable input.
- Ending waits when the consumer disconnects and exposing a cooperative cancellation signal.
- Preserving recoverable-error information instead of presenting every tool failure as a fatal run failure.

The UI SSE handler exposes a `threading.Event` named `cancelled`; the agent checks
it during streamed generation. Its confirmation wait also observes that event.
Cancellation does not forcibly stop Python tool bodies; the separate per-tool
timeout and cooperative cancellation contract is documented under
[Tools](/sdk/core/tools#timeouts-and-cancellation).

For operating the terminal application and its host protocol, see
[the TUI guide](/guides/terminal-hub).
