<Warning>
**Beta.** The SDKs drive `gaiacpp --engine`. Both are tested against the real engine
with a scripted model server. Neither has yet been evaluated on a hosted model, and
the packages are not published: install from `sdk/python` or `sdk/typescript` in the
repository for now.
</Warning>

The SDK runs the GAIA agent loop for a program that is not GAIA: a support bot inside
a web server, a batch job, a Node service. The loop itself runs in the native `gaiacpp`
engine, a single native binary that the SDK starts as a child process. Your tools,
system prompt and conversation stay in your process.

The engine has no tools of its own, reads no settings file, keeps no memory and never
edits the model's answer.

## A first agent

<CodeGroup>

```python Python
from gaia_sdk import Agent, Budget, ToolRefusal, tool

@tool
def get_order(order_number: str) -> dict:
    """Look up an order by its number."""
    if not verified(order_number):
        raise ToolRefusal("That order has not been confirmed in this chat.")
    return {"status": "shipped"}

with Agent(
    model="my-model",
    base_url="https://api.example.com/v1",
    api_key_env="PROVIDER_API_KEY",
    system_prompt="You answer questions about orders.",
    tools=[get_order],
) as agent:
    turn = agent.run("Where is order 1001?", budget=Budget(model_calls=8, seconds=25))
    print(turn.text if turn.ok else f"handing off: {turn.stop_reason}")
```

```ts TypeScript
import { Agent, ToolRefusal, tool } from "@amd/gaia-sdk";

const getOrder = tool({
  name: "get_order",
  description: "Look up an order by its number.",
  parameters: {
    type: "object",
    properties: { order_number: { type: "string" } },
    required: ["order_number"],
  },
  run: async ({ order_number }: { order_number: string }) => {
    if (!(await verified(order_number))) {
      throw new ToolRefusal("That order has not been confirmed in this chat.");
    }
    return { status: "shipped" };
  },
});

const agent = await Agent.start({
  model: "my-model",
  baseUrl: "https://api.example.com/v1",
  apiKeyEnv: "PROVIDER_API_KEY",
  systemPrompt: "You answer questions about orders.",
  tools: [getOrder],
});
try {
  const turn = await agent.run("Where is order 1001?", {
    budget: { modelCalls: 8, seconds: 25 },
  });
  console.log(turn.ok ? turn.text : `handing off: ${turn.stopReason}`);
} finally {
  await agent.close();
}
```

</CodeGroup>

## What you set

| Option (Python / TypeScript) | Meaning |
|---|---|
| `model` | The model id sent to the provider, unchanged |
| `base_url` / `baseUrl` | Any OpenAI-compatible endpoint |
| `api_key_env` / `apiKeyEnv` | The **name** of the environment variable holding the key. The engine reads it; the key is never passed between processes |
| `system_prompt` / `systemPrompt` | Sent to the model as written |
| `tools` | Your functions. In Python the schema comes from type hints and the docstring; in TypeScript you give a JSON Schema |
| `max_steps` / `maxSteps` | Tool-using steps one turn may take |
| `max_output_tokens` / `maxOutputTokens` | Cap on each model reply |
| `budget` | Limits on a turn: model calls, output tokens, seconds, dollars |
| `prices` | The model's list prices per million tokens. Needed for a dollar budget and for the turn's cost: the engine carries no rate card |
| `answer_checks` / `answerChecks` | Functions that compare the answer with the tool calls that ran |
| `on_model_call` / `onModelCall` | Called once per model request with its usage and seconds |
| `before_model_call` / `beforeModelCall` | Called before each model request; it can wait, or stop the turn |
| `engine` | Path to the `gaiacpp` binary, when it is not found otherwise |

## What a turn gives back

`run()` takes the user's message, or the whole conversation ending with it. The engine
keeps no history between turns, so send what the model should see.

| Field (Python / TypeScript) | Meaning |
|---|---|
| `ok` | True when `status` is `success`. Show `text` to an end user only then |
| `status` | `success`, `incomplete`, `failed` |
| `stop_reason` / `stopReason` | `answered`, `max_steps`, `model_calls`, `output_tokens`, `deadline`, `cost`, `model_call`, `unresolved_checks`, `repeated_calls`, `no_answer`, `host_stop`, `cancelled` |
| `text` | The model's answer, exactly as it wrote it |
| `tool_calls` / `toolCalls` | Every tool call in order: name, arguments, result, failed |
| `usage` | Model calls and input, cached and output tokens |
| `cost_usd` / `costUsd` | Those tokens at your `prices`; empty without them |
| `unresolved_checks` / `unresolvedChecks` | What your answer checks still object to after the one repair |
| `failure` | For a failed model request: its kind and message |

A failed model request, a spent budget and a step limit are not exceptions. They are
a turn whose `ok` is false, so one `if` handles all three. `EngineError` is raised only
when the engine itself cannot run the turn.

### One turn at a time

An agent drives one engine process, so it runs one turn at a time. A second `run`
while one is running raises `AgentBusy`; use one agent per thread, or per concurrent
turn in Node. Agents do not share anything, so as many as you like can run side by
side.

If `on_model_call` raises, the turn is still finished first and the error is raised
after it, so the next `run` gets its own answer and not the interrupted turn's.

## Tools

A tool that returns normally gives the model its result. Two other outcomes:

| In the tool | The model is told |
|---|---|
| Return something JSON cannot hold. Python: an object, bytes, `NaN`, a value that contains itself. TypeScript: a `BigInt`, a function, a value that contains itself (`NaN` is sent as `null`) | The call failed, and why. The turn goes on |
| `raise ToolRefusal("...")` / `throw new ToolRefusal("...")` | `{"status": "refused", "message": "..."}` as an ordinary result to explain. Not a failure |
| Any other exception | The call failed, and why. The turn goes on |

### Limiting how often a tool runs

<CodeGroup>

```python Python
@tool(max_calls_per_turn=1, terminal=True)
def handoff_to_human(summary: str) -> dict:
    """Pass the conversation to a person."""
    ...
```

```ts TypeScript
const handoff = tool({ name: "handoff_to_human", description: "Pass the conversation to a person.",
  parameters: { type: "object", properties: { summary: { type: "string" } }, required: ["summary"] },
  maxCallsPerTurn: 1, terminal: true, run: ({ summary }) => openTicket(summary) });
```

</CodeGroup>

A call past `max_calls_per_turn` is not run: the model is told so and asked to answer
from the result it has. After a `terminal` tool succeeds, no other tool runs that turn,
so the model's next reply is its answer.

## Checking the answer against what ran

An answer check gets the answer and the turn's tool calls, and returns what is wrong
or nothing. The SDK sends the problems back to the model once. If the next answer
still fails, the turn comes back `incomplete` with the problems in
`unresolved_checks`, so you can withhold it.

```python
def handoff_was_real(answer, tool_calls):
    said = "passed this to the team" in answer.lower()
    did = any(c["name"] == "handoff_to_human" and not c["failed"] for c in tool_calls)
    if said and not did:
        return "You said this was passed to the team, but handoff_to_human was not called."

agent = Agent(..., answer_checks=[handoff_was_real])
```

## Budgets

A budget is checked when the model asks for a tool. Once a limit is reached the tool is
not run, nothing more is sent to the model, and the turn ends `incomplete` with the
limit as its stop reason. An answer that arrives on the last allowed request is still
an answer.

`seconds` also cuts off a model request still in flight when the time runs out: the
turn ends `incomplete` with `deadline`, to the nearest second, instead of waiting for
a slow provider to answer.

A dollar limit (`usd`) needs `prices`; without them it is refused before anything is
sent, since a limit that cannot be metered would never fire.

## Holding a request back, and stopping a turn

`before_model_call` runs before every model request, retries included. Use it for a
rate limit or a quota you keep yourself.

<CodeGroup>

```python Python
from gaia_sdk import StopTurn

def gate(request):
    wait = limiter.seconds_until_free(account_id)
    if request.seconds_left is not None and wait > request.seconds_left:
        raise StopTurn("account is over its rate limit")
    time.sleep(wait)

agent = Agent(..., before_model_call=gate)
```

```ts TypeScript
import { StopTurn } from "@amd/gaia-sdk";

const agent = await Agent.start({
  ...,
  beforeModelCall: async (request) => {
    const wait = limiter.secondsUntilFree(accountId);
    if (request.secondsLeft !== null && wait > request.secondsLeft) {
      throw new StopTurn("account is over its rate limit");
    }
    await sleep(wait * 1000);
  },
});
```

</CodeGroup>

The request has what the turn has spent so far (`model_calls`, `input_tokens`,
`output_tokens`), `seconds` since it began, and `seconds_left` when the turn has a
`seconds` budget. `StopTurn` ends the turn `incomplete` with `stop_reason`
`host_stop` and your text in `host_stop` / `hostStop`: the request is not sent. Any
other error from the hook ends the turn too, and is raised from `run` once the engine
has finished it.

`agent.cancel()` stops the turn in flight from any thread: the model request or tool
call already running finishes, nothing further is sent, and the turn comes back with
status `cancelled`. With no turn running it does nothing.

## Getting the engine

The SDK looks for `gaiacpp` in this order: the `engine` option, the `GAIA_ENGINE`
environment variable, a binary packaged with the SDK, then `PATH`. Builds for Windows,
Linux and Apple Silicon are attached to each
[GAIA release](https://github.com/amd/gaia/releases), or build it from `cpp/`:

```bash
cmake -B build -S cpp -DCMAKE_BUILD_TYPE=Release
cmake --build build --target gaiacpp
```

### A slim install

The Python SDK has no dependencies, so a server image needs only one wheel:

```bash
python sdk/python/build_wheel.py --engine build/gaiacpp --out dist
pip install dist/gaia_sdk-*.whl
```

The wheel carries the engine and is tagged for the platform it was built on. CI
installs it into an empty environment with no package index and runs a turn through
it, and does the same for the npm package with the binary in its `bin/` folder.
Neither package is published to PyPI or npm yet.

## How this differs from the Python agent

GAIA has a second way to embed the loop: importing `gaia.agents.base.agent.Agent` from
`amd-gaia` ([Embedding GAIA in a Server](/sdk/embedding)). Choose by what you need.

| | `gaia-sdk` / `@amd/gaia-sdk` | `amd-gaia` Python agent |
|---|---|---|
| Runs as | A child process, one native binary | In your Python process, with the full package |
| Languages | Python and TypeScript | Python |
| Install | No dependencies | The whole `amd-gaia` dependency set |
| Tool limits, answer checks, dollar budgets | Yes; you supply the prices | Yes; Fireworks' prices are built in |
| Hook before each model request, cancel a turn | Yes | Yes |
| Stream tokens | Not yet | Yes |
| Maturity | Beta | The loop the desktop apps run |

The wire between the SDK and the engine is documented in
[Engine Protocol](/sdk/host-protocol).
