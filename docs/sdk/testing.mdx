A useful agent test checks both the tool's behavior and whether the harness called
it. An answer string alone does not establish that the tool ran.

Use `catalog_agent.py` from [Build a Python Agent](/sdk/core/custom-agents).
Save the following as `test_catalog_agent.py` beside it, then install pytest:

```bash
uv pip install pytest
```

## Test tool validation directly

```python
from unittest.mock import patch

from catalog_agent import CatalogAgent
from gaia.agents.base import tools as tools_module


def test_stock_validation():
    # Isolate this test's process-global registry and restore it afterward.
    with patch.dict(tools_module._TOOL_REGISTRY, {}, clear=True):
        agent = CatalogAgent(
            catalog={"notebooks": 12},
            skip_lemonade=True,
            silent_mode=True,
        )
        get_stock = agent.get_tools_info()["get_stock"]["function"]
        assert get_stock("notebooks")["quantity"] == 12
        assert get_stock("missing")["status"] == "error"
```

No model request is made. This checks domain behavior but bypasses the harness's
argument coercion, permission checks, and timeout handling. The registry patch is
a test fixture, not a pattern for resetting a running multi-agent service.

## Test model response through dispatch

Add this second test to the same file:

```python
from types import SimpleNamespace
from unittest.mock import patch

from catalog_agent import CatalogAgent
from gaia.agents.base import tools as tools_module


def test_catalog_query_uses_the_tool():
    with (
        patch.dict(tools_module._TOOL_REGISTRY, {}, clear=True),
        patch("gaia.agents.base.agent.AgentSDK") as sdk,
    ):
        sdk.return_value.send_messages.side_effect = [
            SimpleNamespace(
                text='{"tool":"get_stock","tool_args":{"item":"notebooks"}}',
                stats=None,
            ),
            SimpleNamespace(text='{"answer":"12 notebooks"}', stats=None),
        ]
        agent = CatalogAgent(
            catalog={"notebooks": 12},
            skip_lemonade=True,
            silent_mode=True,
        )
        with patch.object(
            agent, "_execute_tool", wraps=agent._execute_tool
        ) as execute:
            result = agent.process_query("How many notebooks are in stock?")

        execute.assert_called_once_with("get_stock", {"item": "notebooks"})
        assert result["status"] == "success"
        assert result["error_history"] == []
        assert result["result"].startswith("12 notebooks")
        assert sdk.return_value.send_messages.call_count == 2
```

Patch `AgentSDK` **where the harness imports it**, in `gaia.agents.base.agent`.
The loop calls `send_messages()`. Patching `gaia.chat.sdk.AgentSDK.send()` does
not intercept this path. The two responses drive a tool call and then completion;
a single repeated tool response can hit loop guards instead of ending the test.

This fixture exercises the prompt-based response path. Native tool-call parsing,
streaming, permission denials, and cancellation need their own tests when your
application uses those paths. `_execute_tool` is an internal test observation
point, not a public API for bypassing the model.

Run both tests:

```bash
uv run python -m pytest test_catalog_agent.py -q
```

## Validate the real integration

After deterministic tests pass, use the actual backend and host you intend to
ship. Check the concrete result: a file contains the requested edit, a lookup
returns the supplied data, or a query uses the intended repository. Exercise a
failure and an approval denial as well as a successful request.

Repository integration tests may depend on `require_lemonade` and other fixtures
in `tests/conftest.py`; those fixtures are not installed with the SDK. Check the
test summary for skipped integrations before claiming a backend was tested.

See [development checks](/reference/dev), [agent evaluation](/reference/eval), and
[tool policy and timeouts](/sdk/core/tools) for the next layer of validation.
