This guide covers common problems people encounter when installing GAIA. If your issue isn't listed here, please [open a GitHub issue](https://github.com/amd/gaia/issues/new) and attach `~/.gaia/electron-install.log`.

## Windows: SmartScreen blocks the installer {#smartscreen}

**Symptom**: Running the `.exe` installer shows "Windows protected your PC".

**Cause**: The installer is unsigned (we're working on Windows code signing — see [#530](https://github.com/amd/gaia/issues/530)).

**Fix**: Click **More info** → **Run anyway**. The installer is safe — you can verify by checking the SHA-256 hash against the [GitHub Release page](https://github.com/amd/gaia/releases/latest).

## macOS: Gatekeeper blocks the app {#gatekeeper}

**Symptom**: A dialog appears saying **"gaia-desktop" Not Opened** — "Apple could not verify gaia-desktop is free of malware…" with only **Move to Trash** and **Done** buttons. Or on older macOS: "GAIA cannot be opened because the developer cannot be verified."

**Cause**: The DMG is ad-hoc signed but not notarized with an Apple Developer ID (we're working on notarization — see [#733](https://github.com/amd/gaia/issues/733)).

**Fix — macOS 15 Sequoia and later:**

1. Click **Done** in the dialog (do not click "Move to Trash").
2. Open **System Settings → Privacy & Security**.
3. Scroll down to the Security section. You will see:
   > "gaia-desktop" was blocked from use because it is not from an identified developer.
4. Click **Open Anyway**.
5. Enter your Mac password when prompted.
6. The app opens. macOS remembers this choice for future launches.

**Fix — macOS 14 Ventura and earlier:**

Right-click (or Control-click) **GAIA** in the Applications folder and choose **Open**. In the dialog that appears, click **Open**.

**Alternative fix — terminal (all macOS versions):**

```bash
xattr -cr /Applications/GAIA.app
```

Then double-click the app — it will open without the Gatekeeper dialog.

## Antivirus flags a GAIA file as an infostealer {#av-false-positive}

**Symptom**: On an older install that still runs GAIA from `.gaia/venv`, your antivirus
quarantines a file under `.gaia/venv/…/gaia/skills/audit/` with a generic Python-malware
name. Current installs run a frozen `gaia` and have no `.gaia/venv`; re-running the one-line
installer moves an older install onto it. The reported case is Bitdefender flagging

```
C:\Users\<user>\.gaia\venv\Lib\site-packages\gaia\skills\audit\__pycache__\code.cpython-312.pyc.2586770202400
as Generic.PY.SordealStealer.A.27B8D72
```

**Cause**: A false positive on GAIA's own credential-stealer *detector*. `gaia/skills/audit/code.py`
is the skill auditor — the code that inspects a third-party skill and refuses it if it reads
your secrets. To do that it has to name what it is looking for: `~/.ssh`, `.aws/credentials`,
`.git-credentials`, browser cookie stores, `base64.b64decode`. Compiled to bytecode, that list
is indistinguishable from an infostealer's target list to a generic heuristic. The detector's
vocabulary is matching a detector.

The trailing number in the filename (`.pyc.2586770202400`) is CPython's atomic-write temp file —
written on your machine the first time GAIA imports that module. The GAIA wheel ships no
`__pycache__` at all, so a flagged `.pyc` is never a file you downloaded.

**Verify it yourself** — this compares every installed file against the SHA-256 recorded in the
wheel's manifest and prints anything that has been altered:

```powershell
# Windows
& "$env:USERPROFILE\.gaia\venv\Scripts\python.exe" -c "import base64,csv,hashlib,pathlib,sysconfig; site=pathlib.Path(sysconfig.get_paths()['purelib']); rec=next(site.glob('amd_gaia-*.dist-info/RECORD')); bad=[p for p,d,_ in csv.reader(rec.open(encoding='utf-8')) if d.startswith('sha256=') and (site/p).is_file() and base64.urlsafe_b64encode(hashlib.sha256((site/p).read_bytes()).digest()).rstrip(b'=').decode()!=d.split('=',1)[1]]; print('modified files:', bad or 'none')"
```

```bash
# macOS / Linux
~/.gaia/venv/bin/python -c "import base64,csv,hashlib,pathlib,sysconfig; site=pathlib.Path(sysconfig.get_paths()['purelib']); rec=next(site.glob('amd_gaia-*.dist-info/RECORD')); bad=[p for p,d,_ in csv.reader(rec.open(encoding='utf-8')) if d.startswith('sha256=') and (site/p).is_file() and base64.urlsafe_b64encode(hashlib.sha256((site/p).read_bytes()).digest()).rstrip(b'=').decode()!=d.split('=',1)[1]]; print('modified files:', bad or 'none')"
```

`modified files: none` means your install is byte-identical to the published wheel.

**Fix**:

1. Report the false positive to your antivirus vendor so the signature gets corrected for
   everyone. Bitdefender takes submissions through its support portal; include the detection
   name and the quarantined path.
2. Nothing needs restoring — the quarantined file was a bytecode cache, and Python rebuilds it
   on the next import. To stop the alert recurring, add an antivirus exclusion for `~/.gaia/`
   (Windows: `%USERPROFILE%\.gaia\`).
3. If the integrity check above lists any modified file, do **not** add an exclusion — re-run
   the one-line installer, which installs a fresh, checksum-verified `gaia`, and
   [open an issue](https://github.com/amd/gaia/issues/new).

## App installs but won't start

### Backend not found
**Symptom**: The app shows "This GAIA install is missing its backend."

**Cause**: The app ships its backend as a `gaia` executable in its `resources/core` folder, and that file is gone. Antivirus quarantining it is the usual reason.

**Fix**: Reinstall GAIA. If your antivirus removed the file, restore it from quarantine or add an exclusion for the GAIA install folder first.

### Tray icon missing
**Symptom**: App launches but no tray icon appears.

**Fix**: On Linux, ensure your desktop environment supports system tray icons (KDE/XFCE work; some GNOME setups need an extension). On Windows, check if the icon is hidden — click the **^** in the system tray to expand hidden icons.

## Update isn't being detected

**Symptom**: A new version is published on GitHub Releases but GAIA doesn't notify you.

**Fix**:
1. Check that `GAIA_DISABLE_UPDATE` is NOT set in your environment
2. The check runs 10 seconds after launch and every 4 hours — be patient or restart the app
3. Check `~/.gaia/electron-updater.log` for any errors
4. As a last resort, download the new installer manually from GitHub Releases

## Uninstall doesn't remove all data

**Symptom**: After uninstalling, data still exists in `~/.gaia/`.

**Cause**: This is intentional — the default uninstall keeps your data so reinstalling preserves your chats and documents.

**Fix**: Run `gaia uninstall --purge` with the `gaia` inside the app, before you uninstall it. The [installation guide](/guides/install#uninstalling) has the command for each platform.

Add `--purge-lemonade` to also uninstall a system-wide Lemonade Server, or `--purge-models` to also remove downloaded models.

## How to attach the install log to a bug report

1. Open the install log with your text editor: `~/.gaia/electron-install.log`
2. Copy the contents (or attach the file)
3. Open a new issue at [https://github.com/amd/gaia/issues/new](https://github.com/amd/gaia/issues/new)
4. Paste the log into the issue body, surrounded by triple backticks
