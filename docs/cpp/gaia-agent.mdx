`gaiacpp` is the general-purpose GAIA agent as one native binary: it reads and writes files, works through documents and data with the programs on the PC, runs shell commands, edits code and fetches web pages. It needs no Python runtime, starts instantly, and stays around 15 MB of memory through a multi-step task.

It runs three ways:

| Mode | Command | For |
|---|---|---|
| Interactive | `gaiacpp` | A person at a terminal |
| Headless | `gaiacpp -p "prompt"` | Scripts, CI, eval harnesses: answer on stdout, exit code 0 or 1 |
| Server | `gaiacpp serve` | Apps and [Lemonade](#lemonade-integration): OpenAI-compatible `/v1/chat/completions` |

## Quick start

```bash
cd cpp
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target gaiacpp
```

With Lemonade running and a model downloaded:

```bash
./build/gaiacpp -p "Summarize the CSV files in this folder" -m Qwen3.6-35B-A3B-GGUF
```

Headless runs deny tools that change things (shell, writes, web) unless you pass `--dangerously-skip-permissions`; each denial is reported on stderr.

## Choosing the model endpoint

`gaiacpp` talks to any OpenAI-compatible endpoint. Settings apply in this order, each overriding the one before:

1. Built-in defaults: Lemonade at `LEMONADE_BASE_URL`, else `http://localhost:13305/api/v1`, and `Gemma-4-E4B-it-GGUF`
2. The settings file: `--config FILE`, else `$GAIACPP_CONFIG`, else `~/.config/gaiacpp/config.json` (`%APPDATA%\gaiacpp\config.json` on Windows) when it exists
3. Environment: `GAIA_BASE_URL`, `GAIA_MODEL_ID`, `GAIA_MAX_STEPS`, `GAIA_CONTEXT_SIZE`, `GAIA_MAX_TOKENS`
4. Flags: `--base-url`, `-m/--model`, `--provider`, `--api-key-env`, `--ctx-size`, `--max-tokens`, `--max-steps`, `--native-tools`

The key for the endpoint is sent as `Authorization: Bearer`. It comes from the variable named by `--api-key-env` (or `apiKeyEnv` in the settings file), else `GAIA_API_KEY`, else `LEMONADE_API_KEY`, which is only ever sent to a loopback address (the local Lemonade). A key is never read from or written to a settings file. A variable that is named but unset stops the agent with an error instead of sending an anonymous request.

`gaiacpp` loads the model at `contextSize` only through Lemonade's `/api/v1` endpoints. Through `/v1`, or any other server, the model runs at whatever window the server gives it.

`--provider fireworks` is shorthand for Fireworks' endpoint with `FIREWORKS_API_KEY` and native tool calls:

```bash
gaiacpp -p "…" --provider fireworks -m accounts/fireworks/models/deepseek-v4p1-flash
```

### Settings file

```json
{
  "baseUrl": "http://localhost:13305/api/v1",
  "modelId": "Qwen3.6-35B-A3B-GGUF",
  "contextSize": 65536,
  "apiKeyEnv": "LEMONADE_API_KEY",
  "nativeToolCalls": "always",
  "mcpConfig": "mcp.json"
}
```

Any [`AgentConfig`](/cpp/api-reference) field is accepted. `provider` (`lemonade` or `fireworks`) and `mcpConfig` (relative to the settings file) are the two extras.

### MCP servers

`--mcp-config FILE` connects every server in an `mcp.json` (`mcpServers` object). Both transports work: `command`/`args` for stdio, and `url` (or `"type": "http"`) for Streamable HTTP, such as Lemonade's own MCP server. Header values may reference variables, for example `"Authorization": "Bearer ${LEMONADE_API_KEY}"`; an unset variable is an error. An env or header value can also be `{"$keyring": "gaia.connections:<connector>:<KEY>"}`, the reference `gaia connectors` writes: `gaiacpp` reads the secret from the OS keyring (Windows Credential Manager, macOS Keychain, or the Secret Service through `secret-tool` on Linux) and keeps it in memory only. A missing secret, or a keyring that can't be reached, stops the agent with the reason. A server that fails to connect stops the agent. A server's tools become the agent's tools; when it also offers resources or prompts, the agent gets `list_mcp_resources` / `read_mcp_resource` and `list_mcp_prompts` / `get_mcp_prompt`, which name the server.

### Where the agent may work

The file, git and shell tools are confined to the working directory (`--cwd`) and any folder added with `--allow-dir DIR`. A file tool given a path outside them is refused, and so is a shell command that names an existing folder outside them, other than system folders such as `/usr`, `/etc` and `/tmp`. The prompt tells the model which folders it has. The shell check reads the command text: it stops an agent from wandering, for example a whole-disk `find` or a path a document planted, but it is not a sandbox. `--full-access` removes the confinement.

### Documents

`index_document` indexes a file or a folder: PDFs (through `pdftotext`, so each passage keeps its page number), Word `.docx`, text, Markdown and code. `query_documents` returns the passages that answer a question, with file and page. Retrieval ranks passages by keywords (BM25), and also by meaning when an embedding model is set with `--embedding-model` or `embeddingModel` in the settings file (`--provider fireworks` uses `nomic-ai/nomic-embed-text-v1.5`); the two rankings are merged. Every result says which mode produced it. A PDF with no text layer, or a file that can't be read, is reported as a failure instead of being indexed empty.

### Code

`index_codebase` indexes a project (default: the working folder), honoring `.gitignore` and skipping `.git`, `node_modules`, virtual environments, build output and files over 1 MB. `search_code` then finds code by keywords or, with an embedding model, by meaning, and returns file paths and snippets. Code has its own index, so document questions never rank source files.

### Models

With Lemonade, `gaiacpp models list` lists the server's models and `gaiacpp models pull <name>` downloads one. A built-in model is pulled by name alone; `--checkpoint` and `--recipe` register a new model and need a name starting with `user.`.

### Images

`analyze_image` sends an image file (PNG, JPEG, GIF, WebP, BMP) to a model that accepts images and returns its answer about it: text, charts, tables, screenshots, photos. It uses the agent's own model unless `--vision-model` names another on the same endpoint. A model that can't read images is reported as an error that says to set `--vision-model`.

### Audio and image generation

`transcribe_audio` turns a recording (wav, mp3, m4a, ogg, flac, webm) into text through the endpoint's `/audio/transcriptions`, and `generate_image` saves a PNG made by `/images/generations`. Lemonade serves both. Each tool exists only when its model is set: `--transcribe-model` (for example `Whisper-Base`) and `--image-model` (for example `SDXL-Turbo`), or `transcribeModel` / `imageModel` in the settings file; `audioBaseUrl` sends transcription to a different host. A failed request is reported with the server's reason.

`--screenshots` adds `take_screenshot`, which saves the screen to a PNG in the working folder (PowerShell on Windows, `screencapture` on macOS, `grim`, `gnome-screenshot`, `scrot` or ImageMagick on Linux) for `analyze_image` to read. It is off by default and asks before each capture, because a screenshot can show anything on screen.

### Memory

`remember`, `recall`, `update_memory` and `forget` keep facts, preferences and notes across sessions in `$GAIA_HOME/memory-cpp.db` (`~/.gaia/memory-cpp.db` by default). Stored preferences are added to the prompt; other facts are found with `recall`, which searches by keyword. Text that looks like a credential is refused. `forget` asks for confirmation. `--no-memory` turns memory off. The file is separate from the Python agent's memory database.

### Skills

`gaiacpp` reads the same `SKILL.md` skills as the Python agent. It lists installed skills in its prompt by name and description, and loads a skill's instructions with `load_skill` when the request calls for it. It looks in these folders, and an earlier folder's skill wins over a same-named one later (`list_skills` reports the shadowed copy):

1. `skills/` beside the `gaiacpp` binary
2. `~/.gaia/skills/` (`$GAIA_HOME/skills` when `GAIA_HOME` is set)
3. `./.claude/skills/` and `~/.claude/skills/`: loadable by name, not listed

A skill that ships Python tools (`tools.py`) loads as instructions only, and `load_skill` says so. `--no-skills` leaves skills out.

`gaiacpp skills install <name>[@version]` downloads a skill from the hub (`GAIA_HUB_URL`, default `https://hub.amd-gaia.ai`), checks the bundle against the SHA-256 the hub lists, and verifies its `SIGNATURE.json` the same way the Python runtime does: Ed25519 over every file's digest, checked against the built-in AMD key and `~/.gaia/skills/trusted-keys.json`. A signature that doesn't verify, or files that changed after signing, stop the install. The signature sets the skill's tier: AMD-signed skills are `verified`, ones signed by a key you trust are `community`, and unsigned ones or ones signed by an unknown key are `experimental`, which install only with `--allow-experimental`. `gaiacpp skills install <folder>` applies the same checks to a local folder. `gaiacpp skills list` and `gaiacpp skills remove <name>` do the rest. Installing is the user's command, not a tool the agent can call.

## Headless runs

```bash
gaiacpp -p "prompt" --output-format json --cwd ./task
echo "prompt" | gaiacpp -p
gaiacpp --prompt-file prompt.txt
```

`--output-format json` prints one line:

```json
{"result": "…", "status": "success", "steps": 5, "tool_errors": 0,
 "model": "…", "duration_s": 6.0, "peak_rss_mb": 14.9,
 "usage": {"prompt_tokens": 17831, "completion_tokens": 735, "total_tokens": 18566}}
```

`status` is `success`, `error` (the model failed, the step budget ran out, or a tool-call loop was stopped) or `cancelled` (Ctrl+C). `peak_rss_mb` is the agent process's own peak memory; programs it ran are not counted. Progress goes to stderr, so stdout carries only the answer.

## Server mode

```bash
SERVE_KEY=$(openssl rand -hex 32) gaiacpp serve --port 0 --server-key-env SERVE_KEY
```

Once bound, the server prints one JSON line on stdout, so a supervisor learns the port:

```json
{"event": "ready", "url": "http://127.0.0.1:41733", "model": "…", "version": "0.1.0"}
```

| Route | Purpose |
|---|---|
| `POST /v1/chat/completions` | Run the agent on the conversation. With `stream: true`, steps and tool activity arrive live as empty-delta `chat.completion.chunk`s carrying a `gaia` field, and the answer follows when the run ends |
| `GET /v1/models` | The agent's model |
| `GET /v1/tools` | The agent's tools and their parameters |
| `GET /health` | Status, version, `busy`. Open without a key, for readiness probes |
| `POST /v1/tools/:name` | Run a tool directly. Off unless `--expose-tool-routes` |

Each request carries its whole conversation, so the server keeps no state between requests. It runs one completion at a time and answers a second with 409. A client that disconnects from a stream cancels the run. A run that fails, runs out of steps or is cancelled comes back as an error (HTTP 500, or an error event on a stream) whose `code` is the run's status, with the agent's own summary as the message; it never ends with `finish_reason: "stop"`.

The server binds `127.0.0.1` and refuses to bind any other address without a key. It sends no CORS headers and rejects requests that carry an `Origin` header unless you allow that origin with `--allow-origin`, and it rejects a `Host` header that isn't `localhost` or a loopback address. A web page in the user's browser therefore can't drive the agent. Tools run without confirmation in this mode: whoever starts the server and holds its key owns that decision.

## Lemonade integration

Lemonade's agent host installs agents from a pinned GitHub release asset, configures them for the local server, and launches them (see Lemonade's `docs/guide/agents.md`). `gaiacpp` provides what that contract needs:

| Lemonade needs | gaiacpp provides |
|---|---|
| A release asset per platform, binary at the archive root, pinned by SHA-256 | `cpp/packaging/package_lemonade.py` builds `gaiacpp-<os>-<arch>.tar.gz` (`.zip` on Windows) and the `agent_versions.json` checksum entry; `build_agents.yml` runs it for each platform |
| Point the agent at this server, without writing the key to disk | The settings file (`baseUrl`, `modelId`, `contextSize`). When lemond has a key, the host adds `apiKeyEnv: "LEMONADE_API_KEY"` and passes the key in the environment; without one it leaves `apiKeyEnv` out |
| Lemonade's tools in the agent | `mcpConfig` naming Lemonade's MCP server by URL |
| A launch command for a terminal | `gaiacpp -m <model>` (interactive) |
| A served agent | `gaiacpp serve --port 0 --server-key-env <VAR>`, ready line on stdout, `GET /health` for readiness |
| No surprise upgrades | `--version`; the binary has no self-update |

Release archives link the C++ runtime statically (`GAIA_STATIC_CXX_RUNTIME=ON`) and need only OpenSSL 3, zlib and zstd from the system on Linux. glibc is the floor of the build host, so build Linux releases on the oldest distribution you support (CI uses `ubuntu-latest`).

## What the agent loop handles

- **Transient failures:** connection errors and HTTP 408, 409, 425, 429 and 5xx are retried with exponential backoff (`llmRetries`, default 3). Other errors fail the turn with the server's message.
- **Full context window:** on an overflow error, older tool outputs are replaced with references and the request is sent once more.
- **Large tool output:** output beyond `maxToolResultChars` (default 16000) keeps its head and tail in the conversation; the model reads the rest with `read_tool_output`.
- **Malformed tool calls:** invalid arguments are returned to the model to resend, up to three times in a row. Whole-string numbers and `"true"`/`"false"` are converted to the declared parameter type.
- **Loops:** the fourth identical call in a row is refused with a note asking the model to change course; a second loop ends the turn.
- **Step budget:** the model is told when few steps remain (default budget 50). At the limit, one call without tools asks for an honest summary of what was done and what wasn't.
- **Claims checked against what happened:** an answer is sent back once when it says it saved a file that doesn't exist, that tests or a command ran when no command ran, or that something is missing when the agent never looked. Agents built on the framework add their own checks by overriding `reviewFinalAnswer()`, using `turnToolCalls()`.
- **"Always allow" is scoped:** in the interactive session, always allowing a shell command covers that program (`pytest`), or program and subcommand (`git status`), or the exact text of a chained or piped command, never every shell command.
- **Reasoning text:** `<think>…</think>` blocks never reach the answer. A reply that is empty, for example reasoning cut off by `maxTokens`, is asked for once more.
- **Cancel:** `requestCancel()` (Ctrl+C, or a server client disconnecting) stops the run at the next step, and mid-stream when the agent streams (`GAIA_STREAMING=1`). A second Ctrl+C exits at once, for a model call or tool that won't return.
- **Web access:** `web_fetch` follows redirects itself and refuses any hop that resolves to a loopback, private, link-local or metadata address, so a page can't steer the agent at Lemonade or other local services. `GAIA_WEB_FETCH_ALLOW_PRIVATE=1` allows the local network.
