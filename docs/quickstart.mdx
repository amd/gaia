Build a Python agent whose tool counts words, then run one model-driven query.
If you want to chat with the flagship instead, follow the [Terminal UI guide](/guides/terminal-hub).

## 1. Prepare Python and the model

Install Python 3.10+ and [uv](https://docs.astral.sh/uv/), then create an environment. On Linux/WSL, append
`--extra-index-url https://download.pytorch.org/whl/cpu` to the
`uv pip install amd-gaia` command below to avoid downloading CUDA packages:

```bash
mkdir gaia-count-agent
cd gaia-count-agent
uv venv
uv pip install amd-gaia
uv run gaia init
```

`gaia init` sets up the local Lemonade backend and models. It can download several
GB. The Python package and `gaia-tui` are separate installations.

## 2. Create an agent with one tool

Save this as `count_agent.py` in the directory you just created. The subclass
registers a word-counting function and tells the model when to call it.
`_register_tools()` is required; `_get_system_prompt()` supplies the instructions.

```python
from gaia.agents.base.agent import Agent
from gaia.agents.base.tools import tool


class CountAgent(Agent):
    def _get_system_prompt(self) -> str:
        return (
            "Use count_words to count words in the user's text. "
            "Report its result."
        )

    def _register_tools(self):
        @tool
        def count_words(text: str) -> dict:
            """Count whitespace-separated words in text."""
            return {"count": len(text.split())}


agent = CountAgent()
result = agent.process_query(
    "Count the words in: GAIA runs on my computer"
)
print(result["result"])
```

## 3. Run a query

Run it with the local backend available:

```bash
uv run python count_agent.py
```

The answer should report **5 words**; its phrasing can vary by model. You may also
see progress and the console-rendered answer before the final `print`.

The tool computes the count; the model chooses the tool call and writes the answer.
If startup fails, resolve the prerequisite reported by `gaia init` in the same
environment. If the turn fails, inspect `result["status"]` and
`result["error_history"]` instead of treating any returned text as success.
See the [agent harness](/sdk/core/agent-system) for the result contract, lifecycle,
limits, and error handling, and [tools](/sdk/core/tools) for registration and permissions.
