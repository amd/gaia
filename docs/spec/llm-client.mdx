title: "LLM Client"
description: "The shared Lemonade and Claude provider contract"
---

GAIA's LLM layer exposes one factory and a shared `LLMClient` interface. The
Lemonade provider serves local models and models configured behind Lemonade,
including on-prem gateways. The Claude provider connects to Anthropic.

## Supported providers

| Provider | Selection | Model lifecycle |
| --- | --- | --- |
| Lemonade | `create_client("lemonade", ...)` or the default | Local load/unload; discovered cloud models bypass local loading |
| Claude | `create_client("claude", ...)` or `use_claude=True` | Provider-managed; local load/unload is unsupported |

The factory lives in `src/gaia/llm/factory.py`. Implementations live in
`src/gaia/llm/providers/`; the common abstract interface and unsupported-operation
exception are in `base_client.py` and `exceptions.py`.

## Removed adapters and migration

The direct `openai` and `litellm` adapters were removed because they discarded
native tool calls. The `litellm` installation extra is removed too. The
`openai` Python dependency remains: Lemonade uses it for compatible HTTP requests.

`provider="openai"`, `provider="litellm"`, and `use_openai=True` raise `ValueError`
with migration guidance before importing a provider or issuing requests.
`use_chatgpt=True` in the agent, chat/audio/talk SDK chain and the legacy
`--use-chatgpt` CLI flag also fail explicitly. These flags are retained only as
migration-error shims; they do not select another backend or ignore the setting.

Configure the upstream model in Lemonade, then pass the Lemonade server URL and
its catalog model ID. Do not substitute a raw upstream endpoint for Lemonade's
URL: a generic OpenAI-compatible service does not implement Lemonade's catalog
and lifecycle API. See [gateway migration](/sdk/sdks/llm#gateway-migration).
Historical release notes describe the providers that shipped in those releases.

## Factory

```python
from gaia.llm import create_client

local = create_client(
    "lemonade",
    base_url="http://localhost:13305/api/v1",
    model="Gemma-4-E4B-it-GGUF",
)
claude = create_client(use_claude=True)
```

An explicit supported provider takes precedence over `use_claude`. Provider names
are case-insensitive. Unknown names fail with the supported list. A true legacy
`use_openai` flag is always rejected, including alongside an explicit provider.
Remaining keyword arguments are passed to the selected provider constructor.

The endpoint and authentication resolver in `lemonade_client.py` supplies the
configured server when `base_url` is omitted. Never embed credentials in prompts,
model identifiers, or a committed configuration example.

## Shared operations

`LLMClient` declares `generate(prompt, ...)` and `chat(messages, ...)` for text
completion and structured conversations. Both support streaming where implemented
by the selected provider. Optional methods include `embed`, `vision`,
`get_performance_stats`, `load_model`, and `unload_model`. Unsupported operations
raise `NotSupportedError`; callers must not silently substitute another provider.

```python
from gaia.llm import NotSupportedError

answer = local.chat([{"role": "user", "content": "Explain this repository."}])
for chunk in local.generate("Summarize these notes.", stream=True):
    print(chunk, end="")

try:
    claude.load_model("a-local-model")
except NotSupportedError as exc:
    print(exc)
```

Lemonade implements local model lifecycle and embedding operations. Cloud models
served through Lemonade have their own capabilities; selecting Lemonade does not
imply that every remote model supports every operation. Claude's provider supports
text and vision but not local model lifecycle or embeddings.

## Native tool-call transport

The shared agent consumes the provider's string response. Lemonade preserves
native calls in the `__tool_calls__` sentinel envelope, including call IDs,
function names and arguments; it does not replace a tool-only response with empty
assistant text. Streaming deltas are accumulated before dispatch so a partial
argument fragment cannot execute as a complete call. The agent turns results back
into the corresponding tool messages for the next model request.

Provider usage is available through `get_last_usage()` when the backend reports
it. Missing usage is not proof of zero tokens or zero cost. Per-turn timing and
usage records are owned by `agents/base/turn_metrics.py`.

## Error boundaries

Configuration errors fail before inference. Lemonade transport errors are
classified by the Lemonade provider into typed failures with user-facing guidance.
Authentication and upstream service failures must remain attributable to the
configured destination; no implicit retry with a different model or provider is
permitted. Optional dependencies must not be required merely to reject a removed
provider name.

## Regression coverage

- `test_llm_client_factory.py`: supported selection and shared interface.
- `test_removed_llm_providers.py`: rejected legacy names and flags across the
  factory, SDK, base agent and CLI, before model initialization.
- `test_lemonade_client.py`: supported Lemonade operations.
- `test_lemonade_cloud_models.py`: local/cloud lifecycle separation.
- `test_parallel_tool_calls.py`: preservation and execution of native calls.

The unit workflow triggers for changes to shared source and the packaged chat
agent. Tests must exercise the retained route as well as migration failures.
