`RAGToolsMixin` registers document tools for an agent. It uses `RAGSDK` for
extraction, embeddings, and retrieval, and the RAG instance's chat client for
summarization. The packaged [ChatAgent](/guides/chat) and [GAIA agent](/guides/gaia)
already supply its host state.

For application code that only needs document Q&A, start with the
[Chat SDK's RAG methods](/sdk/sdks/chat). For agent composition, read the
[tool-mixin guide](/sdk/mixins/tool-mixins) before adopting this component.

## Host agent contract

Import `RAGToolsMixin` from `gaia.agents.tools.rag_tools` and call
`self.register_rag_tools()` inside your agent's `_register_tools` hook.
Registration creates tools in the harness registry. It does **not** add methods
such as `agent.query_documents()` or `agent.summarize_document()` to the host.
Use the agent's normal query/dispatch path to invoke registered tools.

Unlike a self-contained SDK, this mixin depends on host state and helpers:

| Host member | Requirement |
| --- | --- |
| `rag` | Initialized `RAGSDK`; `None` represents unavailable RAG |
| `indexed_files` | A mutable set; successful single-file indexing calls `.add()` |
| `max_chunks` | Base retrieval limit used by the adaptive selection logic |
| `current_session` | Active session object, or `None` for no session persistence |
| `session_manager` | Must provide `save_session` when a current session is active |
| `watch_directories` | Directory list included in `rag_status` |
| `_generate_search_keys(query)` | Supplies query reformulations for retrieval |
| `rebuild_system_prompt()` | Refreshes document context after successful indexing |

Some paths also consult `_is_path_allowed(path)` for the host's file policy.
Review the complete host implementation rather than treating this hook as a
universal boundary on every tool. A working reference is
[ChatAgent](https://github.com/amd/gaia/blob/main/hub/agents/chat/python/gaia_agent_chat/agent.py).

Initialize required state before `Agent.__init__` calls `_register_tools`.
Registration does not validate the contract. Only `rag` is enforced at the point
of use: `query_documents` and `query_specific_file` raise
`MissingHostAttributeError`, naming the host class and attribute, when it was
never set. `None` remains a valid "RAG disabled" value. The other members are
enforced by convention, so missing state may surface only on the first tool call.
[#3316](https://github.com/amd/gaia/issues/3316) records why a construction-time
check was rejected.

## Registered tools

Arguments below describe tool calls, not Python methods on the mixin.

| Tool | Behavior |
| --- | --- |
| `index_document(file_path)` | Index one file; update the host's tracked files and active session on success |
| `index_directory(directory_path, recursive=False)` | Visit supported files and return indexed, failed, and skipped counts |
| `list_indexed_documents()` | Describe the current document collection |
| `rag_status()` | Report index statistics, document types, and watched directories |
| `query_documents(query, debug=False)` | Return retrieved chunks for the agent to use in its answer |
| `query_specific_file(file_path, query)` | Retrieve from a matching document; may discover/index a file when absent |
| `search_indexed_chunks(pattern)` | Case-insensitive literal substring search; return at most 10 matching chunks and the total count |
| `evaluate_retrieval(question, retrieved_info)` | Assess keyword overlap; this is a heuristic, not independent answer verification |
| `summarize_document(file_path, summary_type="detailed", max_words_per_section=20000)` | Summarize cached/extracted text; accepts `brief`, `detailed`, or `bullets` |
| `dump_document(file_name, output_path=None)` | Write cached extracted text to Markdown; default destination is the RAG cache directory |

Directory indexing currently accepts `.pdf`, `.txt`, `.csv`, `.json`, `.py`,
`.js`, `.java`, `.cpp`, `.c`, `.h`, and `.md`. The SDK accepts additional formats
including Word, PowerPoint, and Excel: index those files individually until
[#3871](https://github.com/amd/gaia/issues/3871) aligns folder ingestion.

Use full paths for document-specific operations. Some matching paths use substring
matching and select the first result; a basename shared by multiple documents is
not a reliable identifier.

## Retrieval results

`query_documents` combines embedding results from several search keys with
keyword matches, deduplicates text, and selects chunks using an adaptive limit.
Larger collections can raise that limit above `max_chunks`. These limits bound
chunk counts, not tokens, and do not guarantee that every collection fits a
model's context window.

Successful `query_documents` results include a `chunks` list. Entries carry `content`,
`source_file`, and `relevance_score`; a `page` field is included only when a page
number is found. Check status and field presence before consuming a result.
`query_specific_file` identifies the document at the result level rather than
adding `source_file` to each chunk.
The `debug` argument on `query_documents` is currently unused; debug details
follow the host's `self.debug` setting.

An empty retrieval is different from an unavailable index or a tool error.
Inspect returned `status`, `error`, and `hint` fields. The existing
`query_documents` exception path can return a fallback instruction;
[#3315](https://github.com/amd/gaia/issues/3315) tracks making failures explicit.
Do not interpret that fallback as evidence from the documents.

Page inference can look backward across a document boundary
([#3873](https://github.com/amd/gaia/issues/3873)). Check the source text before
relying on an inferred citation page.

## Summarization limits

The tool splits text at page markers, groups pages with overlap, summarizes each
section, then synthesizes a final answer. A single oversized page or text without
page markers can exceed `max_words_per_section`; the setting is a grouping target,
not a hard token budget.

A section failure is currently logged and skipped. Final synthesis can still
return `status: "success"` with fewer processed sections. Until
[#3872](https://github.com/amd/gaia/issues/3872) makes incomplete coverage explicit,
do not treat that status alone as proof the whole document was summarized.

## Source and validation

The implementation is in
[`rag_tools.py`](https://github.com/amd/gaia/blob/main/src/gaia/agents/tools/rag_tools.py)
and [`RAGSDK`](https://github.com/amd/gaia/blob/main/src/gaia/rag/sdk.py).
For custom-host tests, validate registration and error/result contracts without
inference first, then run indexing and retrieval against a configured embedding
server. See [Testing agents](/sdk/testing) for testing the actual dispatch path.
