GAIA's code index finds source files by meaning. It parses code into chunks, embeds them through your configured Lemonade server, and stores a FAISS index on disk. Use a local Lemonade server to keep embedding requests on your machine; cloud chat can still receive retrieved code as context.

The index is exposed two ways:

- **Tool mixin** — `CodeIndexToolsMixin` powers the flagship [GAIA agent](/guides/gaia)'s `coding` skill and is available to any custom agent that opts in via `KNOWN_TOOLS["code_index"]`.
- **Python SDK** — `CodeIndexSDK` for direct programmatic use.

`gh` is **not** required — the index covers source files only.

## Overview

| Aspect | Details |
|--------|---------|
| **Languages parsed** | Python (AST), JavaScript, TypeScript, Go, Rust, Java, C, C++ |
| **Embeddings** | Via the configured Lemonade Server (`user.embeddinggemma-300m-GGUF` — EmbeddingGemma 300M, 768-dim — by default) |
| **Vector store** | FAISS `IndexFlatL2` |
| **Cache** | `~/.gaia/code_index/<repo-hash>/` (atomic writes; incremental on file-hash) |
| **Privacy** | Sensitive filenames (`.env`, `.pem`, `.key`, …) excluded; inference location follows your server configuration |

## Setup

For a Python installation, add the RAG dependencies:

```bash
uv pip install "amd-gaia[rag]"
gaia init
```

On Linux, append `--extra-index-url https://download.pytorch.org/whl/cpu` to the
install command. From a source checkout, use `uv pip install -e ".[rag]"` with
the same Linux option. Native terminal users can follow the setup checks in
[the Terminal guide](/guides/terminal-hub).

The configured Lemonade server must serve the embedding model. An index records
which model created it; after changing models, rebuild before searching. Matching
vector dimensions alone do not make embeddings from two models interchangeable.

## Using it from the flagship agent

The [`coding` skill](https://github.com/amd/gaia/blob/main/hub/skills/coding/SKILL.md) is what puts the code index in front of the flagship GAIA agent — it lists `search_code_index` among the tools a coding task needs, and directs the agent to run `index_codebase` once per repo before relying on semantic search. Ask the agent to work on a codebase and it calls these tools autonomously:

| Tool | Description |
|------|-------------|
| `index_codebase` | Build / refresh the FAISS index |
| `search_code_index` | Semantic search over indexed chunks |
| `get_index_status` | Report current index state |
| `clear_code_index` | Remove the cached index |

You usually will not have to wait for that first `index_codebase` call. The
[project map](/guides/project-map) starts one in the background at task start
whenever the agent is in a repository that has no index, so by the time a
semantic search matters the index is often already there. Set
`GAIA_PROJECT_MAP_AUTO_INDEX=0` to keep indexing entirely manual.

Ask for a concrete repository and question:

```text
Index ~/projects/my-app and find where authentication errors are handled.
```

Review the returned paths and source before acting on a result. You can then ask
to index another repository within the agent's allowed roots. This switches the
active index; it does not search both repositories together. `get_index_status`
shows which repository is active.

Custom agents compose `CodeIndexToolsMixin` directly in their class declaration; it's also registered in `KNOWN_TOOLS["code_index"]` ([`src/gaia/agents/registry.py`](https://github.com/amd/gaia/blob/main/src/gaia/agents/registry.py)) for dynamic resolution. For SDK-level composition see the [SDK reference](/sdk/sdks/code-index).

## Using it from Python

For direct programmatic use (no agent), call `CodeIndexSDK` yourself:

```python
from gaia.code_index.sdk import CodeIndexConfig, CodeIndexSDK

config = CodeIndexConfig(repo_path="/path/to/repo", max_files=2000)
sdk = CodeIndexSDK(config)

# Build / refresh the index — incremental: unchanged files (matched by
# SHA-256) reuse their existing embeddings
result = sdk.index_repository()
print(f"Files: {result.files_indexed}, Chunks: {result.chunks_created}")

# Semantic search
for r in sdk.search("how does the agent handle errors", top_k=5):
    print(f"[{r.score:.3f}] {r.chunk.file_path}:{r.chunk.start_line}")

# Inspect and manage
print(sdk.get_status())
# Call sdk.clear_index() only when you want to remove this cached index.
```

See the [Code Index SDK Reference](/sdk/sdks/code-index) for the full `CodeIndexConfig`, `CodeIndexSDK`, and data-type reference.

## Cache layout

```
~/.gaia/code_index/
└── <repo-hash>/
    ├── metadata.json    # version, embedding_model, file_hashes, chunk dicts
    └── index.faiss      # FAISS IndexFlatL2 vectors
```

Both files are written atomically (temp file + rename). The cache is keyed by the resolved repo path. If you switch embedding models the metadata mismatch is detected and search raises a `ValueError` until you re-index.

## Privacy and troubleshooting

Sensitive filenames such as `.env`, SSH private keys, and certificate/key files
are excluded during discovery. Check the configured file scope and server before
indexing a private repository.

- **Missing dependencies:** install `amd-gaia[rag]` in the environment running the agent.
- **Embedding service unavailable:** complete `gaia init` and inspect Lemonade's model status.
- **Wrong repository:** ask for `get_index_status`, then index the intended absolute path.
- **Path refused:** choose a repository within the agent's allowed roots. Custom agents
  can configure `ceiling_paths`; see [mixin integration](/sdk/sdks/code-index#agent-integration-codeindextoolsmixin).
- **Embedding model changed:** rebuild the repository index before searching again.

For API fields, parser behavior, and cache controls, see the
[SDK reference](/sdk/sdks/code-index).
