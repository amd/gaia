GAIA is the flagship general-purpose agent. It extends [ChatAgent](/guides/chat)
with the full tool profile, skill management, code search, and image generation.
The [agent harness](/sdk/core/agent-system) runs its reasoning and tools; the
[terminal](/guides/terminal-hub) supplies the interactive interface.

## Install and launch

Install the native terminal package from [GAIA downloads](https://amd-gaia.ai/#install),
then launch:

```bash
gaia-tui
```

The native package includes the terminal and flagship agent executable. Follow the
[Terminal guide](/guides/terminal-hub) for setup, keyboard controls, models, and
permissions. Start with a file summary or a question about your project; the
examples below show how to ask for specific results.

Local inference uses Lemonade and defaults to `Gemma-4-E4B-it-GGUF`. The flagship
manifest declares 8 GB minimum memory and Windows x64, Linux x64, and macOS Apple
Silicon support. Run `gaia init` to set up the local backend and model.

**Local inference is the default, not a guarantee that every operation stays on
this machine.** Web research, downloads, and connectors contact external services.
The stdio terminal also supports explicitly selected Claude and cloud models
exposed through Lemonade; those send conversation data to the provider. Retrieval,
memory, and code indexing still use Lemonade embeddings. See
[AI providers](/guides/ai-providers).

For source development, use the [checkout launch instructions](/reference/tui#run-the-flagship-from-your-checkout).
`GAIA_GAIA_AGENT_MODE=dev` selects source mode for a daemon-backed sidecar; it does
not change a stdio launch. `--dev` enables diagnostics, not source selection.

## Try a task

Use a specific file or folder and describe the result you want. Replace these
example paths with paths on your machine:

| Task | Example request |
| --- | --- |
| Understand a document | “Summarize ~/Documents/report.pdf and identify the main assumptions.” |
| Explore data | “Read ~/Documents/sales.csv and show total sales by region.” |
| Find code | “Index ~/projects/my-app and find where configuration is loaded.” |
| Save a preference | “Remember that I prefer concise answers.” |

Check the returned evidence and tool results before relying on an answer. A tool
may need a model, connector, or installed dependency; GAIA reports that requirement
when it cannot complete the task.

## Capabilities

The full registry includes the following tool groups. Dynamic selection sends a
subset to the model on each call; `load_tools` can bring in additional groups
mid-turn. The registered count is not the per-call prompt size.

| Area | Main tools |
| --- | --- |
| Documents | `index_document`, `index_directory`, `query_documents`, `query_specific_file`, `summarize_document`, `search_indexed_chunks` |
| Files | `read_file`, `write_file`, `edit_file`, `find_files`, `search_file_content`, `browse_directory`, `tree` |
| Data | `analyze_data_file`, `create_table`, `insert_data`, `query_data`, `list_tables`, `drop_table` |
| Web | `search_web`, `fetch_page`, `fetch_webpage`, `download_file`, `search_documentation` |
| Memory | `remember`, `recall`, `forget`, `update_memory`, `search_past_conversations` |
| Images | `analyze_image`, `answer_question_about_image`, `generate_image`, `list_sd_models`, `get_generation_history` |
| Audio/video | `transcribe_media`, `refine_transcript` |
| Desktop/system | `take_screenshot`, `list_windows`, `get_system_info`, `notify_desktop`, `read_clipboard`, `write_clipboard`, `text_to_speech`, `run_shell_command` |
| Skills | `list_skills`, `search_skill_hub`, `install_skill`, `remove_skill`, `load_skill`, `unload_skill`, `skill_status`, `remember_skill_lesson` |
| Code | `index_codebase`, `search_code_index`, `get_index_status`, `clear_code_index` |
| Run control | `request_user_input`, `set_loop_state`, `load_tools` |

Document Q&A supports PDF, Word, PowerPoint, and text. Data tools query CSV/Excel
content through a local SQL scratchpad. Audio tools save and refine transcripts;
see [Transcription](/guides/transcription). Image generation uses local Stable
Diffusion and can evict the resident chat model, requiring a reload afterward.

`run_shell_command` applies an allowlist and rate limit. An active skill grant
can allow a named CLI under its command policy: covered read-only calls can run
without another prompt, while confirmable writes still require approval. This
is not unrestricted shell execution.

## Permissions and file scope

The built-in tools subject to confirmation policy include `write_file`, `edit_file`,
`run_shell_command`, `execute_python_file`, `notify_desktop`, `install_skill`, and
`remove_skill`. The stdio terminal displays confirmations and returns your decision;
bypass mode disables those prompts. See [Terminal permissions](/guides/terminal-hub).

The native terminal normally starts a persistent **stdio subprocess**, which
can ask for approval. A flagship installed as a Hub binary uses a
daemon-supervised **HTTP sidecar** instead.

<Warning>
The HTTP sidecar refuses confirmation-gated actions: its query stream does not
implement an approval/resume flow. This limitation does not apply to the stdio
terminal's interactive approvals.
</Warning>

Confirmation is not a gate on every local write. Indexing, memory updates,
transcripts, and image generation can write state without one of these prompts.

File, document, and data tools default to the user's home directory as their
allowed scope. Resolved-path checks reject paths outside it, including symlinks
that escape the allowed roots. Additional denylists block reading common secrets
and writing automatic-execution locations such as shell startup files and Git
metadata. A rejected path produces an explicit error.

Narrow the scope when embedding the agent:

```python
from gaia_agent.agent import GaiaAgent, GaiaAgentConfig

agent = GaiaAgent(config=GaiaAgentConfig(
    allowed_paths=["/home/me/Documents", "/home/me/projects"],
))
try:
    result = agent.process_query("List files in /home/me/Documents")
finally:
    agent.close()
```

The packaged HTTP sidecar has no `allowed_paths` flag; scope is a construction-time
configuration. The project root described below does not replace this boundary.

## Memory, skills, and projects

Memory is enabled by default. Facts persist on-device; `forget` and `update_memory`
let you remove or correct them. Conversation history, an agent's in-memory state,
and durable memory are different stores. See [Memory](/guides/memory) for storage
and controls.

`gaia-voice` is an always-on skill that sets expectations for honest answers and
reporting actual tool results. The current manifest declares no skill sets, so
leave `GAIA_SKILL_SET` unset; an unknown set fails at startup.

**Installed skills can activate automatically.** Proactive discovery matches a
turn to installed skills; it does not automatically install arbitrary Hub skills.
Dynamic skill selection limits which loaded bodies enter the prompt on a given
turn. Explicit `load_skill` and `unload_skill` remain available.
`GAIA_SKILL_DISCOVERY=0` disables discovery; `GAIA_DYNAMIC_SKILLS=0` keeps loaded
bodies active on every turn. See [Composing skills](/guides/composing-skills).
`remember_skill_lesson` stages a correction; activating it requires the user's
`gaia skill deltas --approve` action.

The [Project map](/guides/project-map) supplies repository context and can build a
semantic code index at task start. Set `GAIA_PROJECT_ROOT` when the launch directory
does not identify the repository, or configure `project_root` in Python.
`GAIA_PROJECT_MAP_AUTO_INDEX=0` disables automatic indexing. The root chooses where
code search starts; `allowed_paths` defines where it may reach.

## HTTP sidecar

With `--serve`, the executable exposes a loopback HTTP service, normally supervised
by the daemon. Its default port is 8141. The native stdio launch does not require
this endpoint. The HTTP query route accepts only `provider: "lemonade"` or an
omitted provider; other values receive **400**. That transport constraint should
not be read as a guarantee that a model exposed by Lemonade is local.

| Endpoint | Purpose |
| --- | --- |
| `GET /health` | Liveness without contacting Lemonade |
| `GET /version` | Daemon contract probe |
| `GET /v1/gaia/version` | Client capability negotiation |
| `GET /v1/gaia/init` | Readiness without pulling or loading a model |
| `POST /v1/gaia/query` | One turn streamed as SSE |
| `POST /v1/gaia/query/{run_id}/cancel` | Cooperative cancellation |
| `POST /v1/gaia/query/{run_id}/respond` | Answer a pending user question |

Readiness checks Lemonade reachability, its supported version floor, and model
availability. It returns **200** when ready or **503** with a corrective hint.

### Authentication

The daemon supplies a per-session bearer token using
`GAIA_GAIA_SIDECAR_TOKEN_FILE`, an owner-only token file. A manually launched
sidecar can also accept `GAIA_GAIA_SIDECAR_TOKEN`. Authenticated requests send
`Authorization: Bearer <token>`; invalid or missing credentials receive **401**.
`/health`, `/version`, and `/v1/gaia/version` are exempt from token checks.

Loopback Host validation and browser Origin checks apply independently. An invalid
Host receives **400** and a non-loopback Origin receives **403**. With neither
token variable supplied, manual development launches disable token checking with
a log warning; Host and Origin checks remain active.

### Requests and session lifetime

`query`, `run_id`, and `context` are required. Mint a UUID before each request so
you can cancel immediately. Send `context: []` for a new conversation; later
requests push the transcript slice in the body. A stable `session_id` retains the
agent, indexed-document state, and loaded skills. Without it each request uses a
temporary agent.

For a manually launched sidecar whose token you supplied:

```bash
curl -N http://127.0.0.1:8141/v1/gaia/query \
  -H "Authorization: Bearer $GAIA_GAIA_SIDECAR_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"query":"Hello","run_id":"70f35976-37b5-4468-841e-e49fef658e38","context":[],"session_id":"example-session","can_answer_questions":false}'
```

Use a fresh run UUID next time. Set `can_answer_questions: false` when no caller
can respond to a mid-run question. Every stream ends with exactly one `final` or
`error`; idle streams send keepalive comments while tools are working.

Only one turn may run per HTTP session. Concurrent turns or a changed model on an
existing session receive **409**. Finish/cancel the active turn, or use a new
session to change models. Idle expiry and capacity eviction can discard retained
state; reclaiming an evicted session emits a warning. Durable memory is separate.

## Troubleshooting

- **Backend/model not ready:** run `gaia init`; HTTP clients can inspect `/v1/gaia/init` for the failing prerequisite.
- **Access denied:** check the resolved path against `allowed_paths` and the secret/write denylists.
- **Source changes have no effect:** inspect the discovered executable and transport; rebuilding the TUI does not rebuild the agent.
- **A file write is refused over HTTP:** use the stdio terminal for interactive tool approval.
- **Sidecar startup fails:** inspect `gaia daemon agents` and `~/.gaia/agents/gaia/logs/sidecar-<port>.log`.

See [TUI debugging](/reference/tui#debugging) for subprocess logs, event traces,
and the distinction between terminal state and daemon state.
