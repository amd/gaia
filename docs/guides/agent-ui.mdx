Ask your PC to find that contract you downloaded last month. Drop in a spreadsheet and get an instant analysis. Search across thousands of files in seconds. GAIA Agent UI is one chat window for the GAIA agent. It runs on your PC by default, and uses a cloud provider (Fireworks AI or the AMD LLM Gateway) only when you pick one of its models.

  New to GAIA? Start with the [Quickstart](/quickstart) for first-time setup, then come back here.
</Info>

**Two commands to get started:**

```bash
npm install -g @amd-gaia/agent-ui
gaia-ui
```

The first time it opens, the app sets itself up: it installs GAIA's local model server, downloads the models and checks they load, with each step shown in the window. No accounts or API keys are needed to run locally.

## What You Can Do

### Find Anything on Your PC

Ask the agent to locate files across your drives — by name, type, content, or recency. No more digging through folder trees.

> *"Find all Python files in my Downloads folder"*
>
> *"Show me the largest files on my Desktop"*
>
> *"Search my project for files that import pandas"*

The agent searches your common folders first, then offers a deep search across all drives if nothing turns up.

### Continue Work Across Turns

In-process chat agents retain file reads, tool calls and tool results for later
questions, including after the server restarts. Complete older turns leave the
model's context only when its estimated history budget fills; the transcript and
stored evidence remain on your machine. When more older turns leave the model's
view — a long chat, or a switch to a smaller model — the chat shows one quiet
line before the reply — "Older messages are now out of the model's view (N
turns)" — and the TUI shows the same line in its transcript. Ask GAIA to recall
anything from before it. A Hub-installed GAIA agent relayed from the Agent UI
sees only the last 5 exchanges, and the chat says so once, when the sixth one
lands. Earlier conversations saved before this feature retain text only.
If the current prompt leaves no history budget, GAIA warns and sends no older
turns; saved evidence remains intact. Switching to a model without native tool
calling replays recorded calls and results as text.

For Fireworks, AMD gateway, and catalog-discovered cloud models, history admission uses a conservative 64K
budget, independent of local device settings and `GAIA_CTX_SIZE`; this is not
a claim about the remote model’s actual context capacity. Claude uses its provider
budget.

With a cloud model selected, the model chip and the sidebar's location line name
the provider (for example **Fireworks AI**) instead of **Local**. They say
**Local** only when GAIA confirms the chat is answered on this PC, and make no
claim when it can't tell. Hover either for what is sent: the whole conversation,
including anything read out of files, documents or memory, which themselves stay
stored on your machine.

### See How Full the Context Is

The meter beside the model chip shows how much of the model's context window the
next message carries. Click it for the breakdown: system prompt, tools,
documents, conversation, and the room kept free for the reply. Before older
turns leave the model's view, a note above the message box names them by their
question. GAIA never summarises or compacts a chat to make room: older turns stay
saved, and you can ask GAIA to recall them.

### Type While GAIA Works

You can keep typing while a reply runs. Press Enter and the message waits in a
queue above the message box, then goes out as its own turn as soon as the reply
ends, in the order you typed. To add a detail to the work already running, press
**Add to this reply** on a queued message: GAIA reads it at its next step
without starting over, though it may not answer it separately. If the reply
ends before reading it, it goes back in the queue. Press Stop and anything still
queued goes back into the message box.

### Compare Models on Your Question

To see how another model answers, use **Retry with…** on the latest answer and
pick a model downloaded on this PC. Both answers appear side by side with the
time each took and its speed. **Keep this answer** on either one, and the chat
continues from it. The other model answers from what the first reply already
gathered and doesn't run tools again. It loads after the first answer, since
the model server holds one model at a time, so the reported time includes
loading it. Your next message loads the chat's own model again.

### Analyze Any Document

Drag files into the chat — or just ask the agent to find them. It indexes the content and lets you ask questions, extract data, compare sections, or get summaries. Works with:

| Category | Formats |
|----------|---------|
| **Documents** | PDF, Word, PowerPoint, Excel, TXT, Markdown |
| **Data** | CSV, JSON, XML, YAML, HTML |
| **Code** | Python, JavaScript, TypeScript, Java, C/C++, Go, Rust, Ruby, Shell |
| **Config** | INI, CFG, TOML |

> *"Summarize this PDF in 3 bullet points"*
>
> *"Compare these two contracts and list the differences"*
>
> *"What's the total spend in this expense report?"*

## The window

The app opens straight to an empty chat: a message box, the model it will use,
and where that model runs.

- **Sidebar:** New chat, search, **Memory**, **Scheduled tasks**, **Documents**,
  then your chats grouped by Today, Yesterday, Previous 7 days and older. At the
  bottom: where answers are generated right now (for example
  `Local · Gemma-4-E4B-it-GGUF` or `Fireworks AI · glm-5p3-flash`),
  notifications, mobile access and Settings. Collapse it with `Ctrl+B`.
- **Message box:** **+** attaches files (or drag them in), the shield picks the
  permission mode, the model chip picks the model, and Send turns into Stop
  while GAIA is working.
- **Tool steps** show as one quiet line ("3 steps · 1 tool") you can open for
  the detail. "Steps" is the agent's own count, the same figure the TUI and
  evals report.
- **The line under an answer** says how long it took, where it ran and when
  the first word came ("Answered in 40 s on your GPU · first word in 1 s", or
  "via Fireworks AI" for a cloud model). Click it for the exact numbers,
  including the tokens the whole turn read and wrote across every model call.
  Files the answer names by full path,
  such as a saved deliverable, open in your file explorer when clicked.
- **A new chat** greets you, shows the folder GAIA works in, and offers up to
  four tasks from the skills you have and what you've set up (indexed
  documents, a connected mail account). A task with a subject to fill in is
  typed into the message box; the others start straight away.
- **"Loading Qwen3.6-35B-A3B on your GPU… 12s"** under the message box means
  the model is loading and reading GAIA's instructions ahead of your first
  message, so that message gets a quick answer. You can type and send
  meanwhile; a message sent early waits for it to finish rather than starting
  over.

Every chat runs the GAIA agent. Chats made by the retired `chat`, `doc` and
`file` agents stay readable but can't be continued; start a new chat instead.

## Models and where they run

Open **Settings → Model** (or the model chip in the message box):

| Provider | What it needs | Where your chat goes |
|---|---|---|
| **Local** | Nothing; pick CPU, GPU or NPU for new chats | Stays on this PC |
| **Fireworks AI** | An API key | Sent to Fireworks AI (usage may be charged) |
| **AMD LLM Gateway** | A gateway key (and URL, if not the default) | Sent to your gateway |

- Keys are masked, go only to GAIA's local model server and your OS credential
  store, and are refused over mobile access. When a key is already set (in the
  environment or from the TUI) the screen says so; leave the field blank to keep
  using it. **Forget key** removes it here and for future sessions.
- Recommended Fireworks models are ranked first, each with the benchmark result
  behind the pick.
- The model you choose is remembered across restarts (shared with the TUI). If
  it can't be restored, a one-line notice says why and asks you to pick one.
- Switching from a local model to a cloud one shows the privacy note first.

### When GAIA's model server runs

Local chat runs on GAIA's own Lemonade Server, the one `gaia init` installs.
GAIA manages it for you, and it gives its memory back when you stop using GAIA:

| When | What happens |
|---|---|
| You open the app (desktop, `npx @amd-gaia/agent-ui`, or `gaia-tui`) | GAIA's background service starts the server if it is not running |
| You close the last GAIA app | Every model is unloaded, so your GPU memory is free again. The server itself stays up for a quick next launch |
| Another GAIA process is still using it, or a request is in flight | Nothing is unloaded until it is done |
| No GAIA process has held it, and it has served no request, for 15 minutes | The server stops entirely |
| A GAIA process sends a request after it stopped | It starts again and the request goes through, after a cold model load |
| `gaia daemon stop` | The server stops, including the one first-time setup started |

Every GAIA process that talks to the server holds a lease on it while it
runs: the app, each `gaia` command, sidecar agents, and a process started with
another `GAIA_HOME` that points `LEMONADE_BASE_URL` at this server. The server
is never stopped while a lease is held or a request is in flight.

The server keeps the same port from one start to the next, and moves only if
another program has taken it. Its API key still changes on every start; read
the current one from `~/.gaia/lemonade/env.sh` (`env.ps1` on Windows).

Fifteen minutes balances giving the GPU memory back to other apps against
the cost of a cold model load, about 20 to 60 seconds, the next time you use
GAIA. Change it, or turn the timeout off with `0`:

```bash
gaia config set lemonade_idle_timeout_minutes 30
```

The new value applies within seconds; no restart is needed.

None of this applies to a Lemonade Server you run yourself and point GAIA at
with `LEMONADE_BASE_URL`: GAIA never unloads its models or stops it.
### Which server and which GPU backend

**Settings → Advanced → Model server** shows what is actually running:

- **Server**: GAIA's own Lemonade or yours (another Lemonade on this PC, or one
  on another machine), with its version.
- **Address**: the URL and port GAIA talks to.
- **Chat model** and **Runs on**: the loaded model and its llama.cpp backend
  (Vulkan, ROCm, CPU), NPU, or *Remote (cloud)*. "Lemonade's default" means the
  load did not name a backend and Lemonade picked it. *unknown* means this
  Lemonade does not report it.
- **Context window** and the **Embedding model** with its backend.

To choose the backend, pick **Auto**, **Vulkan**, **ROCm** or **CPU** under
*llama.cpp backend for chat models*. Only backends Lemonade can run on this PC
are listed; one marked "downloads on first use" is fetched by Lemonade the
first time it loads (ROCm is about 4 GB). The choice applies the next time the
chat model loads; **Reload chat model now** applies it at once. The embedding
model keeps its own backend.

The same setting from a terminal:

```bash
gaia config set llamacpp_backend rocm   # vulkan | rocm | metal | cpu | auto
```

**Change model** opens Settings → Model. To use a different server, set
`LEMONADE_BASE_URL`.

## Permissions

GAIA asks before it changes files, runs commands or uses tools that act for you.
The question appears above the message box with three answers:

- **Allow once**
- **Always allow** *this exact action* in this chat (offered only when the action
  is narrow enough to name, e.g. *writing notes.md*)
- **Deny**

When the same question comes back after you allowed it once, the prompt says
so and highlights **Always allow**. It never answers for you, and a different
tool or a riskier call gets no hint.

Pick **Full access** from the shield to let a chat run everything without
asking (you confirm once). **Settings → Permissions** lists every chat with full
access or "always allow" answers and lets you revoke them. Grants end when GAIA
restarts.

A Hub-installed GAIA, which runs as its own process, follows the chat's mode
too, from agent contract 2.14. It stops asking, but its shell guardrails stay
on. If the mode can't be passed on when a turn starts, that turn stops with an
error, so it never runs with full access you turned off.

## Undo a turn

Before GAIA changes a file, it saves a copy. When a turn changed files, its
answer shows **Review changes** and **Undo this turn**:

- **Review changes** shows what the turn did to each file, as a diff.
- **Undo this turn** puts every file back as it was before the turn: edited
  and deleted files get their old contents, new files are removed. It works
  after GAIA restarts too.

Undo is all or nothing. If you, or a later turn, changed one of those files
since, GAIA names it and changes nothing; you can then undo anyway and lose
that later change. Undo the later turn first to keep it.

GAIA can't copy what a shell command, a Python snippet or a connected (MCP)
tool is about to change. When a turn ran one that could have changed files,
the answer says **Undo may be incomplete** and lists it.

**Settings → Privacy → Undo history** sets how long copies are kept (7 days by
default) and how much space they may use (500 MB, oldest first), and shows how
much they use now.

## Settings

One window with General (appearance: Light, Dark, Match system; shortcuts),
Model, Permissions, Skills (what GAIA can load, with **Use** to try one),
Connectors, Memory, Privacy and Advanced (model server and llama.cpp backend,
context size, custom model ID, beta options, MCP servers, version and roll
back).

**Settings → Advanced → Model server** switches between GAIA's own Lemonade
Server and one you already run: enter its address (and its API key, if it needs
one) and choose **Use this server**. The setup screen offers a Lemonade it finds
running the first time. GAIA never changes your server's setup: connecting a cloud
provider uses the one your server already has, and says so if it has none. **Use
GAIA's own** is refused, with nothing changed, when GAIA's own server isn't
installed; `gaia init --gaia-lemonade` installs it and switches. See
[Use a Lemonade you already run](/guides/install#use-a-lemonade-you-already-run).

## Roll back to a previous version

If an update introduces a regression, you can roll back to a specific earlier release directly from the app — no need to hunt down an old installer on GitHub.

**How to roll back (desktop installer only):**

1. Open **Settings → Advanced**.
2. Click **"Roll back to a previous version"**.
3. The app fetches the list of published releases from GitHub and shows them newest-first, with your currently installed version marked.
4. Click an older release to open a confirmation step.
5. Confirm — the app downloads the selected version and shows a native "Restart now?" prompt when ready. Click Restart and the older version launches.

**Version pinning (AC2):** After a manual rollback, auto-update is automatically paused. The About section shows "Auto-update paused (pinned to vX.Y.Z)" so you know it's held. Click **Resume updates** in the same section to re-enable normal auto-updates.

### Platform support

| Platform | Rollback support |
|----------|-----------------|
| Windows (NSIS installer) | Full — download + reinstall works end-to-end |
| macOS (DMG/ZIP, signed builds) | Works on signed release builds; unsigned dev builds download but cannot apply the update |
| Linux AppImage | Supported (self-replacing) |
| Linux .deb | Not supported via in-app rollback — use `sudo apt install ./gaia-agent-ui-<version>-amd64.deb` from [Releases](https://github.com/amd/gaia/releases) |

<Note>
The rollback list only shows releases that have an installer for your current platform. Releases without a matching artifact are filtered out automatically.
</Note>

## Sessions and Shortcuts

Sessions let you organize conversations by topic. They sync between the CLI (`gaia chat`) and the Agent UI — start in one, pick up in the other. Export any session as Markdown or JSON from the session menu.

| Shortcut | Action |
|----------|--------|
| `Enter` | Send message |
| `Shift+Enter` | New line |
| `Escape` | Stop agent response |
| `Ctrl+K` | Search chats |
| `Ctrl+Shift+O` | New chat |
| `Ctrl+B` | Show or hide the sidebar |
| `Ctrl+,` | Settings |

When GAIA asks permission, the prompt takes focus and `Enter` does nothing, so a message you were typing can't approve it. `Escape` denies (it takes priority over stopping the reply); `Tab` to **Allow once** or **Always allow** and press `Enter` or `Space` to approve. The prompt counts down the time the agent will wait, and GAIA denies when it runs out.

## Long Responses

A chat reply has no time limit while the agent is making progress: model output, a tool starting or finishing, any step. A running tool, or a question or permission prompt waiting on you, also counts, since each has its own time limit. A model that stops sending is handled by GAIA's model-stall check, which ends and retries the request.

GAIA stops a reply only after 75 minutes with no progress at all, and the reply says so: "This turn ran for 75 minutes without progress, so GAIA stopped it." Anything finished before then is kept; send "continue" to pick up where it left off. Change the window with `GAIA_STREAM_TIMEOUT`, set before GAIA starts:

```bash
export GAIA_STREAM_TIMEOUT=7200   # seconds without progress; whole number from 1 to 86400
gaia chat --ui
```

An invalid value (not a whole number, or out of range) stops the Agent UI server at startup with an error naming the variable, rather than quietly using the default.

## Scheduled Tasks

Run a prompt on a recurring schedule — "every morning at 9, summarize my inbox" — without leaving the UI. Click **Scheduled tasks** in the sidebar to open the Schedule Manager.

Describe the schedule in natural language; the parser previews the interpretation live before you create it:

| Input | Meaning |
|-------|---------|
| `every 30m` | Every 30 minutes |
| `every 6 hours` | Every 6 hours |
| `daily at 9pm` | Once a day at 21:00 |
| `every monday at 8am` | Weekly on Mondays at 08:00 |
| `every hour from 8am to 6pm` | Hourly inside a time window |

Each schedule runs in its own chat session, so the full history of runs (prompt + response per run) is one click away via the session list. Pause, resume, or delete schedules from the panel; run counts and the next-run countdown update live.

Behavior notes:

- Scheduled runs use the GAIA agent and the model you picked; with a local model nothing leaves your machine.
- Runs are **suspended while mobile access (tunnel) is active**, matching the autonomous agent loop's security posture. Set `GAIA_AUTONOMOUS_ALLOW_TUNNEL=1` to override.
- One run executes at a time; overlapping schedules queue.
- Per-run timeout defaults to 300 s; override with `GAIA_SCHEDULE_TIMEOUT`.
- Times are your local time, taken from the browser's time zone, and stay put across daylight-saving changes. A time skipped when clocks jump forward runs just after the jump; a time repeated when they fall back runs once. Schedules made before this was fixed were read in UTC; they move to this PC's time zone on the next start.

The REST API lives at `/api/schedules` (create/list/get), `/api/schedules/{name}` (pause/resume/cancel via `PUT`, delete via `DELETE`), `/api/schedules/{name}/results` (run history), and `/api/schedules/parse` (natural-language preview).

## Policy Alerts and Receipts

When a governance-enabled agent blocks a tool call, the Agent UI shows a
non-actionable policy alert instead of an approval prompt. Policy blocks appear
as inline **Policy Shield** activity cards, critical notifications, and a toast
with a **View receipt** link when a receipt ID is available.

Policy alerts are durable session history. If you reload the UI or reconnect
after a blocked request with no assistant text, the block reason, rule IDs,
policy version, and receipt ID remain attached to the assistant message.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Lemonade Server not running">
    You shouldn't have to start the model server yourself — `gaia daemon` starts and supervises it. So the question is why that didn't happen.

    ```bash
    gaia daemon status            # the daemon reports the model server it supervises
    gaia daemon start             # if no daemon is running
    gaia daemon logs --lines 100  # daemon up but no model server — the reason is here
    ```

    The usual cause is that GAIA isn't set up yet. The app shows its setup steps in that case; `gaia init` from a terminal does the same.
  </Accordion>

  <Accordion title="No model loaded">
    ```bash
    gaia download --agent chat
    ```
  </Accordion>

  <Accordion title="Port 4200 already in use">
    ```bash
    # npm CLI
    gaia-ui --port 8080

    # Python CLI
    gaia --ui --ui-port 8080
    ```
  </Accordion>

  <Accordion title="Database locked error">
    Close any other GAIA Agent UI or CLI instances. Only one writer at a time is supported.
  </Accordion>

  <Accordion title="Document indexing fails">
    - Ensure the file is a supported format and does not need a password to open (PDFs with only permission restrictions index fine)
    - Keep file size under 100MB
    - For PDF image extraction, download the VLM model: `gaia download --agent chat`
  </Accordion>

  <Accordion title="Access denied: path must be within one of ...">
    Documents can only be read from an allowed root. By default that is your
    home directory — a file elsewhere on disk is rejected with HTTP 403.

    This bites on service accounts and CI runners, whose home
    (`C:\Windows\System32\config\systemprofile`) is not where their files live.
    Add the extra directory before starting the server:

    ```bash
    # POSIX — separate multiple roots with ':'
    export GAIA_DOCUMENT_ROOTS=/srv/corpus
    ```
    ```powershell
    # Windows — separate multiple roots with ';'
    $env:GAIA_DOCUMENT_ROOTS = "C:\actions-runner\_work\gaia\gaia\eval\corpus"
    ```

    Each entry must be an absolute path to a directory that exists; a relative
    or missing one fails the request with HTTP 500 rather than being ignored.
    The containment check still applies — declaring a root widens access to
    that root only, never to its parent, and a symlink escaping it is still
    rejected.

    Two limits worth knowing before you set this:

    - A declared root is **browsable and previewable, but not searchable**.
      File search and "open in file manager" still only look at your home
      directory, so files under a declared root are reachable by path but will
      not turn up by name.
    - The roots apply to **every client of the backend**, including one
      reaching it over the tunnel feature. Declare only what you would be
      comfortable serving remotely.
  </Accordion>

  <Accordion title="First-run network egress to huggingface.co">
    The first time you index a document, Lemonade Server pulls the embedding
    model (`user.embeddinggemma-300m-GGUF`, ~334 MB) from `huggingface.co`,
    cached under `~/.cache/huggingface/hub/`. Subsequent runs are offline.

    If your environment blocks `huggingface.co`, pre-seed the cache on a
    machine with internet access and copy it to the target machine, or set
    `HF_HOME` to point at a pre-populated cache directory before launching
    the UI.
  </Accordion>

  <Accordion title="Frontend shows JSON instead of the UI">
    The Agent UI frontend has not been built.

    **npm install (`gaia-ui`):** This is handled automatically — `gaia-ui` tells the Python server where to find the pre-built frontend. If you still see this error, try reinstalling: `npm install -g @amd-gaia/agent-ui@latest` Then restart with `gaia-ui`.

    **Source/dev installs (git clone):** Run `gaia init` to build it automatically, or manually (from the repo root):

    ```bash
    cd src/gaia/apps/webui && npm install && npm run build
    ```

    Then restart `gaia chat --ui`.

    **pip/PyPI installs (without gaia-ui):** Use the [npm install path](#install) — the pip package does not include frontend source files.
  </Accordion>

  <Accordion title="LLM response times out or fails">
    If you see "I wasn't able to generate a response" errors, check your MCP server configuration. Misconfigured or unreachable MCP servers cause the agent to wait up to 10 seconds per server before responding.

    Check your config:

    ```bash
    # macOS / Linux
    cat ~/.gaia/mcp_servers.json

    # Windows (PowerShell)
    Get-Content "$env:USERPROFILE\.gaia\mcp_servers.json"
    ```

    If it contains servers you don't recognize or aren't running, either remove them or reset the file:

    ```json
    { "mcpServers": {} }
    ```

    You can also manage MCP servers through the Agent UI settings panel or with the CLI:

    ```bash
    gaia mcp status
    ```
  </Accordion>
</AccordionGroup>
