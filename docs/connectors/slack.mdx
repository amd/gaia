## What you'll need

The connector is an **MCP server**. GAIA starts
[`slack-mcp-server`](https://github.com/korotovsky/slack-mcp-server) through
`npx` (pinned to `slack-mcp-server@1.3.0`) when an agent needs it, and the
agents you grant it to can read channels, threads, and direct messages.
The original `@modelcontextprotocol/server-slack` package is deprecated, so
GAIA uses this maintained replacement.

It needs one secret: a **Slack bot token** (`xoxb-…`). It lives in your OS
keyring, and the server gets it through a `$keyring` reference when it starts.

<Note>
  The server can't post messages or add reactions unless you turn that on
  yourself, and GAIA leaves it off. Bot tokens also can't use Slack's
  message search, so `conversations_search_messages` isn't available.
</Note>

## Step 1 — Create a Slack app and copy its bot token

**From the Agent UI (easiest):** open **Settings** → **Connectors** → **Slack**
and click **Create Slack app**. Slack opens with a read-only app named GAIA
already filled in, so you don't pick any permissions yourself.

1. Pick your workspace and click **Next**, then **Create**. If you own the
   workspace, Slack shows **Create and Install** instead. The list only shows
   workspaces your browser is signed in to. If yours is missing, sign in to it
   at [slack.com](https://slack.com/signin) and click **Create Slack app** again.
2. If Slack asks, install the app to your workspace and click **Allow**. You
   need permission to install apps in the workspace: guest accounts can't, and
   some company workspaces need an admin to approve new apps first.
3. Slack may show a **GAIA is ready!** box with commands to install the Slack
   CLI and run a project. GAIA doesn't need them: click **Go to App Settings**.
   Open **OAuth & Permissions** in the left menu and copy the **Bot User OAuth
   Token**. It starts with `xoxb-`.
4. In Slack, invite the bot to each channel it should read
   (`/invite @GAIA`). A bot sees only the channels it's in.

**By hand:** go to <a href="https://api.slack.com/apps" target="_blank">api.slack.com/apps</a>
→ **Create New App** → **From scratch**, pick your workspace, and under
**OAuth & Permissions** → **Bot Token Scopes** add:
`channels:history`, `channels:read`, `groups:history`, `groups:read`,
`im:history`, `im:read`, `mpim:history`, `mpim:read`, `users:read`, and
`usergroups:read`. Then follow steps 2–4 above, inviting the bot by the name
you gave your app.

## Step 2 — Configure GAIA

**From the CLI:**

```bash
gaia connectors configure mcp-slack --set SLACK_MCP_XOXB_TOKEN=xoxb-...
```

**From the Agent UI:**

1. Launch the Agent UI: `gaia chat --ui`.
2. **Settings** (gear) → **Connectors** → click the **Slack** tile.
3. Paste the token into the **Slack bot token** field and click **Save**.

Either path saves the token in your OS keyring and writes only a `$keyring`
reference into `~/.gaia/mcp_servers.json`. The token is never written to disk
in plaintext.

## Step 3 — Use it

Saving the token doesn't yet let GAIA use Slack. Turn on the **GAIA can use
Slack in chat** switch on the Slack tile. From the CLI, grant **and**
activate the connector; activation is off by default:

```bash
gaia connectors grants grant mcp-slack installed:gaia --scopes "*"
gaia connectors activations activate mcp-slack installed:gaia
```

Then start a new chat and ask something like *"Summarise today's messages in
#general."*

GAIA starts the server with only its read tools: `channels_list`,
`channels_me`, `conversations_history`, `conversations_replies`,
`users_search`, `usergroups_list`, and `usergroups_me`. The server's other
tools (join, leave, and mark-as-read for channels, and user-group edits)
need scopes the Step 1 app doesn't have, so GAIA doesn't offer them. GAIA
can only read channels you invite it to.

## Common issues

### `not_in_channel` or an empty channel history

The bot hasn't been invited to that channel. Run `/invite @your-app-name` in
the channel and ask again.

### "The Slack bot token should start with xoxb-"

You copied a different value from Slack's app page, such as the signing
secret or an app-level token (`xapp-…`). Open **OAuth & Permissions** and
copy the **Bot User OAuth Token** instead.

### `invalid_auth` / `missing_scope`

The token is wrong, revoked, or missing a scope from Step 1. The Slack server
checks its token when it starts, so **Check** on the tile (or
`gaia connectors test mcp-slack`) reports a revoked or wrong token as
"didn't start", with Slack's reason under **Details**. Add the scope,
reinstall the app to the workspace, then **Disconnect** the tile (or
`gaia connectors disconnect mcp-slack`) and configure it again with the new
token.

### The connector times out on its first start

On a cold start, `slack-mcp-server` fetches your workspace's full user and
channel list before it answers GAIA. GAIA waits 10 seconds for MCP servers to
connect, which a very large workspace can exceed. Add a longer `timeout`
(seconds, at most 600) to the `mcp-slack` entry in `~/.gaia/mcp_servers.json`,
for example `"timeout": 120`. Configuring the connector again rewrites the
entry, so add it back afterwards. Later starts read the cached lists and
connect quickly.

### `npx: command not found`

`slack-mcp-server` is started through `npx`. Install Node 18+ and make sure
`npx` is on your `PATH`.

## Revoking access

- **From GAIA:** Settings → Connectors → Slack → **Disconnect** (or
  `gaia connectors disconnect mcp-slack`). This deletes the token from the
  keyring, removes the entry from `mcp_servers.json`, and clears every
  per-agent grant.
- **From Slack:** open your app at
  [api.slack.com/apps](https://api.slack.com/apps) → **OAuth & Permissions** →
  **Revoke All OAuth Tokens**, or uninstall the app from the workspace.
- **Cached lists:** `slack-mcp-server` keeps your workspace's users and
  channels in `*_users_cache.json` and `*_channels_cache_v2.json` files, and
  **Disconnect** doesn't remove them. Delete the `slack-mcp-server` folder
  under `%LocalAppData%` on Windows, `~/Library/Caches` on macOS, or
  `~/.cache` on Linux.
