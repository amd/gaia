This guide explains how to test the Agent UI's Electron shell (`src/gaia/apps/webui/`) and keep it working through dependency updates. The Agent UI is the only Electron app GAIA ships.

## Quick Start

```bash
# Install test dependencies
cd tests/electron
npm install

# Run all Jest suites
npm test

# Run one suite
npm test -- test_electron_chat_app.js

# Watch mode for development
npm run test:watch

# Generate coverage report
npm run test:coverage
```

A few helpers don't fit Jest's CommonJS mocking and run under `node:test` instead:

```bash
node --test tests/electron/test_port_manager.mjs tests/electron/test_loadapp_query.mjs
```

The Agent UI's React components have their own Vitest suite: `cd src/gaia/apps/webui && npm test`.

## Test Structure

All Electron tests live under `tests/electron/`. Shared setup is in `tests/electron/setup.js`; the `electron` and `electron-updater` mocks are under `tests/electron/mocks/`.

- `test_electron_chat_app.js` - Agent UI structure, configuration and frontend wiring
- `test_electron_chat_installer.js` - Packaging and first-run installer readiness
- `test_agent_process_manager.js` - Backend Python process lifecycle
- `test_notification_service.js` - Notification plumbing
- `*.test.cjs` - Main-process services: tray, auto-updater, backend installer, deep links, quit handling and more

## GitHub Actions Integration

`.github/workflows/test_electron.yml` runs on pull requests and pushes to `main` that touch `src/gaia/apps/webui/` or `tests/electron/`, on merge-queue runs, and on manual dispatch. Its jobs:

1. **test-electron-framework** - every Jest suite in `tests/electron/` plus the `node:test` helpers, with coverage uploaded as an artifact
2. **test-webui-vitest** - type-check, Vitest component tests, the right-to-left layout check and the browser auto-scroll check
3. **test-apps-integration** - the Agent UI process manager and notification service suites
4. **test-sigterm-quit** - launches the real Electron on Linux and macOS and checks SIGTERM quits it

## Debugging Tests

```bash
# Run one suite with verbose output
npm test -- test_electron_chat_app.js --verbose

# Debug in Node.js
node --inspect-brk node_modules/.bin/jest --runInBand
```

### VS Code Debugging

Add to `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "launch",
      "name": "Jest - Current File",
      "program": "${workspaceFolder}/tests/electron/node_modules/.bin/jest",
      "args": [
        "${fileBasename}",
        "--runInBand"
      ],
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}/tests/electron"
    }
  ]
}
```

## Common Issues

### Cannot find module 'electron'

**Cause**: Electron is mocked in tests, and the mock mapping is missing or wrong.

**Solution**: Check `moduleNameMapper` in `tests/electron/package.json`:

```json
"moduleNameMapper": {
  "^electron$": "<rootDir>/mocks/electron.js",
  "^electron-updater$": "<rootDir>/mocks/electron-updater.js"
}
```

### Tests time out

**Cause**: An async operation never completes, or a timer outlives the test.

**Solution**:

```javascript
// Increase the timeout for one test
it('slow test', async () => {
  // test code
}, 10000);
```

If a suite passes but Jest hangs on exit, a service interval is still running. Clear it in `afterEach`, or pass `--forceExit` as CI does for the process manager suite.

### Coverage below threshold

1. Run `npm run test:coverage`
2. Open `coverage/lcov-report/index.html`
3. Add tests for the uncovered paths
